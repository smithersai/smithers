# Invariants

Every promise the merge queue makes, and the Lean theorem that proves it.
`lake build` checks this file: each `Proved` row must name theorems that exist
in the model (`MergeQueue/Matrix.lean`), and no declaration may rest on `sorry`
or on an axiom beyond Lean's own three (`MergeQueue/Audit.lean`).

A row, and what the build does with it:

```text
invariant  The target is always green
status     Proved
theorems   main_always_green, ...
build      fails if a named theorem is gone, renamed or rests on sorry
```

- **Proved**: the named theorems state it for the model and the build checks them.
- **Assumed**: true of the world around the queue; the model takes it as given and says so.
- **Open**: not proved yet. The row says what is missing.

## The model in one paragraph

A **tree** is the list of change revisions applied to the target, in order.
The queue's state is the target's tree, every change ever enqueued, the CI
runs it holds (each on one exact tree, with the results streamed so far), the
record of landings and a bounded history of check durations. `step` applies one
event; an event whose guard fails changes nothing. `plan` picks the queue's
next decision from the state alone. `Reachable` is every state `step` can
produce from the empty queue, and `Inv` is the invariant proved for all of
them by induction over events.

## Safety

| Invariant                                                                                                                                                                                                                                                                         | Status | Theorems or reason                                                                                               |
| --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------ | ---------------------------------------------------------------------------------------------------------------- |
| **Main is always green.** The target's tree is the empty tree it started from or exactly the tree of a recorded landing. Every landing the queue made was on a complete green result; the only other landings are commits someone else put on the target, which the record marks. | Proved | `main_always_green`, `landings_form_one_chain`, `green_checked`, `Reachable.inv`                                 |
| **The tested tree is the merged tree.** The queue records a landing only for the run it pushed, onto the tree of that run, whose result is complete and green for that tree.                                                                                                      | Proved | `land_tree_was_tested`, `land_needs_a_push`, `main_moves_only_by_land`, `unknown_run_never_lands`                |
| **The target only fast-forwards.** No event reorders or removes what is on it.                                                                                                                                                                                                    | Proved | `main_only_grows`, `land_fast_forwards`                                                                          |
| **Streaming never lets a partial result merge.** A run that misses a required check, or has a failed check, cannot land.                                                                                                                                                          | Proved | `partial_result_never_lands`, `failed_result_never_lands`, `green_complete`, `green_not_failed`                  |
| **Fixing starts at the first failure.** One failed check lets the lone suspect of a run be blamed, without the run being complete.                                                                                                                                                | Proved | `blame_at_first_failure`                                                                                         |
| **No change is lost.** A change the queue has seen stays in its record under the same id and priority, and an ended change never changes again.                                                                                                                                   | Proved | `never_lost`, `ended_is_final`                                                                                   |
| **Every change ends.** When the queue is quiet (nothing to decide, no run pending, no push under way, no fix agent working) every change is merged, unmergeable or withdrawn.                                                                                                     | Proved | `quiet_means_done`                                                                                               |
| **No change merges twice.** The target's tree applies each change at most once, and a change is recorded as merged exactly when the tree holds it at that revision.                                                                                                               | Proved | `merged_at_most_once`, `merged_iff_in_main`                                                                      |
| **Order and priority are respected.** The ready list is sorted by priority, then arrival; a run tests the first ready changes; nothing ready is overtaken.                                                                                                                        | Proved | `State.ready_sorted`, `State.ready_exact`, `start_takes_the_first`, `nothing_overtaken`, `earlier_arrival_first` |
| **A fix re-queues at the back.** A fixed change returns at its next revision with a new arrival number above every arrival so far, and no other change moves, so a fix never jumps ahead of the runs in flight.                                                                   | Proved | `fix_requeues_at_the_back`                                                                                       |
| **Higher priority lands first.** A change with a higher priority is before one with a lower priority, whenever they arrived.                                                                                                                                                      | Proved | `higher_priority_first`                                                                                          |
| **A change that has not ended can always be withdrawn**, unless it is already on its way onto the target, in which case it lands.                                                                                                                                                 | Proved | `withdraw_takes_effect`, `pushing_change_is_not_withdrawn`                                                       |
| **Unmergeable only with a recorded reason.** Every unmergeable change carries written words; a verdict without words is refused.                                                                                                                                                  | Proved | `unmergeable_has_reason`, `wordless_verdict_refused`                                                             |
| **A fix is tested afresh.** After a fix answer, no run the queue holds is live with the fixed change in it; the new revision lands or is blamed only on a run started after the fix.                                                                                              | Proved | `fix_is_tested_afresh`                                                                                           |
| **Stale answers are refused.** A fix answer or a verdict for another attempt changes nothing.                                                                                                                                                                                     | Proved | `stale_fix_refused`, `stale_verdict_refused`                                                                     |
| **Fix attempts are bounded.** No change uses more fix attempts than `maxAttempts`.                                                                                                                                                                                                | Proved | `attempts_bounded`                                                                                               |
| **Runs are bounded.** No more undecided runs than `maxRuns`; run ids are never reused; a run holds one result per required check.                                                                                                                                                 | Proved | `runs_bounded`, `run_ids_unique`, `results_are_clean`                                                            |

## Crash and restart

| Invariant                                                                                                                                                           | Status | Theorems or reason                                      |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------ | ------------------------------------------------------- |
| **Every event keeps every invariant**, whatever it is and whenever it arrives.                                                                                      | Proved | `Inv.step`, `Reachable.inv`                             |
| **A crash keeps every invariant.** Losing any set of runs at any moment leaves a state that satisfies the invariant, with the target and every change as they were. | Proved | `crash_keeps_invariant`, `crash_keeps_main_and_changes` |
| **Delivering an event twice is delivering it once**, so a driver that does not know whether its last event was recorded can send it again.                          | Proved | `step_idempotent`                                       |
| **Losing or cancelling a run forgets that run and no other.**                                                                                                       | Proved | `cancel_keeps_other_runs`                               |
| **The next decision is a function of the durable state.** A restart resumes from the state alone.                                                                   | Proved | `plan_ignores_history`                                  |

## Progress

| ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **No deadlock.** With something to check and a run slot, a queue with nothing to decide and a change still waiting has a pending run or a push under way: it waits on CI or on the target, never on itself.                                          | Proved | `no_deadlock`                                                                                                                                                                                                                                                                    |
| **Every decision takes effect.** The policy never proposes an event the queue refuses.                                                                                                                                                               | Proved | `plan_takes_effect`                                                                                                                                                                                                                                                              |
| **Fix loops terminate.** Every blame, fix answer and landing that takes effect strictly lowers a budget that only a new change can raise.                                                                                                            | Proved | `budget_blame_lt`, `budget_fixed_lt`, `budget_land_lt`, `budget_never_rises`, `budget_unchanged`, `budget_push`, `budget_foreign`                                                                                                                                                |
| **Bisection terminates.** A bisection run is strictly between the longest prefix not known to fail and the shortest prefix known to fail, and every free run slot takes a split point, so with enough slots the culprit is found in one CI duration. | Proved | `bisection_narrows`, `bisectStep_bounds`                                                                                                                                                                                                                                         |
| **One measure for the whole queue.** A single number that strictly decreases on every decision and every answer, so that fair CI and fix agents imply every change ends.                                                                             | Open   | The budget covers landings, blames and fixes, and `bisection_narrows` covers each bisection step. Still to prove: starts and cancels between two budget drops are bounded by one measure. The implementation checks it by fuzz (`test/Invariant.test.ts`, "the policy settles"). |

## Everything is rebased on the tip of the target

Will, 2026-11-10: "the way a merge queue works is you rebase all the changes on tip of main ... Make sure the merge
queue checks for being main." The queue has one tree it lands on, the target's. There is no side branch.

| Invariant                                                                                                                                                                                                                                        | Status | Theorems or reason                                                              |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------ | ------------------------------------------------------------------------------- |
| **A run is built on the tip of the target.** A start makes a run whose base is the target's tree at that moment, plus the first ready changes.                                                                                                   | Proved | `run_starts_on_the_tip`, `start_takes_the_first`                                |
| **What lands is the tested tree, and it descends from the tip.** A landing moves the target from its tip to that tip plus the tested parts: a fast-forward.                                                                                      | Proved | `land_fast_forwards`, `land_tree_was_tested`                                    |
| **There is no side branch.** Only a landing or someone else's commit moves the one tree the queue has, and both append to it.                                                                                                                    | Proved | `main_moves_only_by_land`, `main_only_grows`                                    |
| **A moved target kills every run on the old tip.** After someone else puts a commit on the target, no run the queue holds is live.                                                                                                               | Proved | `foreign_kills_every_run`                                                       |
| **Nothing tested on a stale tip lands.** After the target moved, a landing for any run the queue held is refused: the case where the target moves between test and land.                                                                         | Proved | `moved_target_refuses_landing`                                                  |
| **A moved target never stops the queue.** The commit is accepted in every state, costs no budget, leaves every queued change queued to be tested on the new tip, and the queue is not idle afterwards unless CI or the target owes it an answer. | Proved | `moved_target_keeps_the_queue`, `moved_target_makes_progress`, `budget_foreign` |

## The queue never blocks

Will, 2026-11-10: "you should never block new commits. The merge queue, if built correctly, should absolutely churn
through it." The model has no paused, frozen or held state; these rows say what that guarantees.

| Invariant                                                                                                                                                                                                                                              | Status | Theorems or reason                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Intake is never refused.** In every state a change with a new id is accepted and queued.                                                                                                                                                             | Proved | `enqueue_always_accepted`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| **Intake disturbs nothing in flight.** A run that could land before a change arrived still can; runs and the target are untouched.                                                                                                                     | Proved | `enqueue_keeps_runs_live`, `enqueue_keeps_runs_and_main`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| **A green run always lands**, whatever any other change is doing: failing, being fixed or waiting. With no push under way it is pushed; once the target is seen on its tree the landing is recorded. No repair holds a landing back.                   | Proved | `green_run_is_always_pushed`, `green_run_always_lands`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| **A change being fixed is out of the way.** It is not in the ready list, so nothing waits for it.                                                                                                                                                      | Proved | `fixing_is_out_of_the_way`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| **A free slot is always used.** While a change waits, no run is pending and no push is under way, the policy has a decision to make.                                                                                                                   | Proved | `free_slot_is_used`, `no_deadlock`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| **A failing change is found without waiting for the changes ahead of it.** A probe tests one ready change alone on the tip; an idle queue with a free slot has every ready change under such a test; a failed one is blamed at its first failed check. | Proved | `probe_is_on_the_tip`, `idle_means_every_change_is_probed`, `blame_at_first_failure`                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| **Throughput keeps up with intake.** With `maxRuns` slots and batches of `maxBatch`, the queue lands at least as fast as changes arrive.                                                                                                               | Open   | Measured, not proved. `scripts/benchmark.ts` (400 changes, CI run = 1 unit, batches of 8 to 16): landed per unit at 5% failing changes is 3.96 on 8 slots (4 arriving), 7.49 on 16 (8 arriving), 13.62 on 32 (16 arriving), 19.95 on 64 (32 arriving); at 10% failing it is 3.97, 6.65, 12.64 and 20.46. With probes the rate no longer collapses as more changes fail; it is about a third of the slots, at about 4 CI runs per landed change. Without probes it was 6.5 on 64 slots at 10%. The model proves the queue is never idle with work it could start. |

## What the queue keeps between rounds

The state the theorems above are about never forgets a change or a landing. The
driver carries less: `State.pruned`, the changes that have not ended and no
landings. How each change ended goes to a record outside the state. These rows
say that forgetting changes nothing the queue does.

| Invariant                                                                                                                                                                                                                                                                                                              | Status  | Theorems or reason                                                                                                                                                                                                                                                                                                                                                                      |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **The pruned queue makes the same decision.** `plan` on the pruned state is `plan` on the full state.                                                                                                                                                                                                                  | Proved  | `pruned_plan`                                                                                                                                                                                                                                                                                                                                                                           |
| **An event on the pruned queue is the pruning of that event on the full queue**, for every event that does not hand in the id of an ended change, in every state whose changes have distinct ids.                                                                                                                      | Proved  | `pruned_step`, `State.pruned_pruned`                                                                                                                                                                                                                                                                                                                                                    |
| **A whole trace and a whole round agree.** From any reachable state, the queue that prunes after every event ends in the pruning of what the full queue ends in, through the events the world reports and through the policy's settling. So every invariant above holds of the full state the pruned queue stands for. | Proved  | `pruned_run`, `pruned_settle`, `pruned_round`                                                                                                                                                                                                                                                                                                                                           |
| **The policy never hands in a change**, so its decisions keep the rule below by themselves.                                                                                                                                                                                                                            | Proved  | `plan_fresh`                                                                                                                                                                                                                                                                                                                                                                            |
| A change id is never used again.                                                                                                                                                                                                                                                                                       | Assumed | `Event.fresh`. The pruned queue no longer holds an ended change, so it cannot refuse its id; whoever hands changes in must not reuse one. The file inbox passes over an `enqueue` line whose id an earlier line enqueued, and the repository numbers foreign commits from a counter. An ended change's own commit pushed to the target by someone else arrives as a new foreign commit. |

## What the model assumes

| Invariant                                       | Status  | Theorems or reason                                                                                                                                                                                          |
| ----------------------------------------------- | ------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| The target branch only moves forward.           | Assumed | Branch protection forbids rewriting it. Others may add commits (the queue adopts them, `foreign`); nobody removes one. The driver reads the real tip every round and fast-forwards with a compare-and-swap. |
| A tree is determined by its parts in order.     | Assumed | The driver builds a candidate by applying exactly those revisions in that order, and lands the commits CI tested, never a rebuild.                                                                          |
| CI reports a verdict for the tree it was given. | Assumed | A result names its run, and a run names one tree; `step` records a result only on the run it names (`results_are_clean`).                                                                                   |
| CI and fix agents eventually answer.            | Assumed | Progress theorems say the queue is never the one that is stuck; they cannot make the world answer. A lost run is `cancel`, after which the policy starts it again.                                          |

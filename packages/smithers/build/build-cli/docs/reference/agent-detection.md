# Agent detection evidence

Verified on 2026-09-04. This registry records **runtime-injected child-process
markers**, not whether an agent is installed or configured. Detection selects an
output experience; it must never grant permissions or bypass approvals.

The absence of a marker does not prove a human is present. An agent can use a PTY,
a human can redirect output, shells can strip variables, and nested agents can
leave several markers. Keep explicit audience selection available and represent
non-interactive automation separately from a positively identified harness.

## Deliberate exclusions and coverage gaps

| Harness or signal                                 | Why it is not sufficient                                                                                                                                                                                                                                                                                                                                                                             |
| ------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Aider                                             | Its [command runner](https://github.com/Aider-AI/aider/blob/5dc9490bb35f9729ef2c95d00a19ccd30c26339c/aider/run_cmd.py) uses inherited shell environment; no dedicated injected marker was found in this path. `AIDER_*` options and provider API keys may be set in a human's shell.                                                                                                                 |
| OpenHands                                         | The inspected [terminal environment builder](https://github.com/OpenHands/software-agent-sdk/blob/f47083cc370a85160f0348f32e531ee3514399e5/openhands-tools/openhands/tools/terminal/env.py) and subprocess/tmux backends sanitize/inherit environment and add shell mechanics, without a verified dedicated agent marker. Container names, usernames, and workspace paths are not identity evidence. |
| Factory Droid                                     | The [official CLI reference](https://docs.factory.ai/droid-cli/cli-reference) documents credentials and configuration, not a stable injected child-shell identity marker. Third-party claims about `DROID`, `DROID_AGENT`, `DROID_SESSION_ID`, and `FACTORY_DROID` were not adopted without vendor-source evidence.                                                                                  |
| Windsurf/Cascade                                  | No stable child-shell identity marker was verified in official documentation. `TERM_PROGRAM`, editor installation, and `WINDSURF_*` configuration cannot distinguish an agent from a human's editor terminal.                                                                                                                                                                                        |
| Google Antigravity                                | Third-party libraries mention `ANTIGRAVITY_AGENT`, but vendor-source confirmation was not found in this audit. Do not silently promote the claim to a verified marker.                                                                                                                                                                                                                               |
| Kiro / Amazon Q                                   | [Official CLI reference](https://kiro.dev/docs/cli/reference/cli-commands/) documents settings and logging variables, not a confirmed agent child-shell marker. Authentication/configuration and general terminal integration are insufficient.                                                                                                                                                      |
| Copilot in VS Code                                | `COPILOT_CLI=1` covers CLI subprocesses, not every VS Code agent. Do not use `TERM_PROGRAM=vscode`, `VSCODE_PID`, or a Copilot extension path as proof.                                                                                                                                                                                                                                              |
| `AMP_THREAD_ID`                                   | [Amp portals](https://ampcode.com/docs/orbs/portals) inject it into service processes; the inspected binary also uses it for a permission helper. Prefer `AGENT=amp` or `AMP_CURRENT_THREAD_ID` for agent commands.                                                                                                                                                                                  |
| `OPENCLAW_CLI=1`                                  | Identifies CLI ancestry broadly, not whether the current command was requested by an agent.                                                                                                                                                                                                                                                                                                          |
| API keys, home/config variables, executable paths | Prove configuration or installation, not agent execution. Never scan or echo secret values for audience detection.                                                                                                                                                                                                                                                                                   |
| `CI`, non-TTY streams, `TERM=dumb`                | Useful rendering/automation hints, not proof of an AI agent.                                                                                                                                                                                                                                                                                                                                         |

## Maintenance contract

- Prefer vendor documentation or the actual child-process environment constructor.
- Record the expected value and scope; do not match every product-prefixed variable.
- Reject empty/disabled marker values and test false positives explicitly.
- Keep detection a pure function over an injected environment and terminal facts;
  do not walk processes, read credentials, scan home folders, or run agent binaries.
- Preserve every matched harness as evidence when agents are nested; do not guess
  which one is the immediate parent.
- Explicit human/agent selection must override heuristics. Structured output and
  MCP must remain machine-clean regardless of the audience override.
- Recheck vendor evidence before extending this list. Unknown harnesses can select
  agent presentation explicitly without requiring a registry update.

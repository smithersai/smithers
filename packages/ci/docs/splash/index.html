How it works

  1. Inventory

    Reads what your CI does today from GitHub Actions workflows, a Justfile, a Makefile, package.json scripts or Turborepo, as shell commands.

  2. Targets

    Turns each command into a Smithers build target with a content key, so a target reruns only when something it reads changes.

  3. Replay

    Runs your past commits in a copy of the repository: once as your CI runs today, once in normal mode, and once in fast mode if you ask.

  4. Report

    Prints the time each way, the speedup it measured, and every target whose pass or fail differs from your CI.

Two modes

Normal mode

Runs every target a change affects and reuses a result only when its key matches. The replay checks every verdict against your CI.

Fast mode

Also skips targets a scorer judges safe to skip. A skipped target is reported as skipped, never as passed, and never cached. The replay counts every failure it would have missed.

Your numbers, not ours

Smithers CI prints the speedup it measures on your own commits. This page shows none, because none has been measured on a repository outside Smithers yet.

Commands

bunx smithers-ci
Measure today's CI, replay past commits, and print the speedup. Writes nothing to the repository.
bunx smithers-ci inventory
Print what the repository's CI does today.
bunx smithers-ci replay
Replay past commits and print the replay report.
bunx smithers-ci apply
Write the Smithers workspace, target files and CI workflow the report was measured with.

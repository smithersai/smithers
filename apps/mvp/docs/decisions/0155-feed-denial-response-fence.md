# 0155 · Authorize the feed when it emits

2026-11-03 · Implements Will's feed repair requests; no new product policy.

After Electric's finite JSON response is buffered, one Postgres statement reads the person's current deployment receipt, session validity, repository access projections and permitted notification subjects. The newest persisted deployment receipt wins, including an explicit null role and receipts on another or ended session. Explicit sessionless local development uses its injected actor. Session and role deadlines use the database clock. The snapshot admits only current subjects under the current membership/`mine` rule and readable repository access. It distinguishes the resolver's actual configured grant routes, including the App, allowlist and explicit local policy. In the statement, current installation state selects the installed or uninstalled route: the deployment repository requires its current deployment receipt; an independently granted installed repository requires its fresh permission receipt; a public-copy route requires current public visibility and deployment membership even if installation metadata is present. A missing/expired independent receipt does not block an installed public copy that the resolver authorized through its public route. Explicit local development uses its injected grants, evaluated after buffering. A scoped `mine` row never bypasses its repository authority. Fleet rows also require the incident kind's current role or committer audience, shared with the delivery flow in `FleetAudience`. A Member who committed the TODO can retain failed/stalled/cost alerts; waiting and offline never admit the committer alone, and cost/offline require Admin otherwise. The proxy then drops every insert or update outside that subject set, including historical fleet inserts whose subjects were pruned. An optional payload repository must agree with the current subject. Deletes contain primary keys only. A concurrent change can withhold rows; an old actor or cached payload cannot add authority.

`ShapeProxy.rowAccess.validate` runs once after buffering and before `allows`, so the app prepares this single snapshot there. A failed snapshot returns private no-store 503 without a cursor. The same snapshot identifies retained, still-projected subjects excluded by current authority. If an actual buffered value names one, `retryIfDenied` returns 503 without advancing the cursor: restoration or renewal may otherwise leave the source row and projection unchanged, permanently skipping the insert. Deleted subjects and rows already withdrawn by a projection can be dropped safely because deletion or a recovery insert is represented in Electric. This post-filter cursor decision reads no new authority and adds no sequence fence. After buffering, sorted feed locks protect one transaction whose single authority statement also deletes fleet rows outside a confirmed current audience. The statement excludes its deleted subjects explicitly, since data-modifying CTE reads otherwise see their starting snapshot. Unknown or expired authority does not prune. These deletes happen after the upstream body and its offset were captured, so a skipped cached insert is followed by its actual delete; stable demotion does not leave the feed retrying forever. Existing receipt-side pruning fences remain unchanged. `notifications.access.emit` logs and spans subject/repository/replay/pruning counts and cursor stability, and the existing pruning counter records deleted fleet rows; the existing shape records count completions and refusals. No payload or credentials enter these records.

Fences protect cursor progress, not disclosure. A poll that crosses a projection reduction or pruning cannot acknowledge an offset that might skip its delete. Recovery and newly permitted repositories use the emit snapshot directly; they need no comparison against the request's older readability decision. A permitted projection write retains its pre-authorization denial sequence and uses a compare-and-set under sorted feed locks. An older allow cannot reopen access over a recorded denial. Withheld projections adopt the resolver's fence under the lock. A readable-to-withheld transition advances the sequence; an identical withheld decision does not. `RepoRoles.remember` keeps receipt-side fencing for actual projection reductions or notification pruning, in the same transaction as the accepted role receipt. Restoration cannot erase a pruning fence. Repeated denials without a reduction or delete leave it alone.

Pure deployment-role receipts neither change projections nor delete rows, so their fences and authority-rank columns are removed. The emit snapshot reads those receipts directly. A loss and restoration without projection or subject changes can therefore return the currently permitted rows without invalidating the cursor.

This extends core authorization using the existing catalog entries Effect SQL and `@smthrs/effect-electric`; no new dependency or feature plugin. Regression tests use real Postgres and Electric with the existing GitHub service seam, including cached payload replay and concurrent requests.

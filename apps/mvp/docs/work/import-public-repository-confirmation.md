Confirm every repository reference anonymously before retaining it in public issue content. Explicit private names override confirmation. Record per-run verdicts in the private plan and sidecar. Regression tests run on cfbox through nyc-01, before and after implementation. One commit; no landing or push.

The catalog's GitHub entry is `@smthrs/integrations` for product code. This existing standalone Node operations command keeps its dependency-free ESM boundary and uses injected native fetch for anonymous verification: it must neither load the authenticated client nor spawn a credential-aware tool. No new library or runtime is introduced.

References are normalized case-insensitively, including GitHub URL and `.git` spellings. The existing decoded-text readings and credential redactions run before discovery; strict repository verdicts replace the static public list only for the importer. Exact fields (including keys and destinations) fail closed. Every generated node is checked, and children whose parent is denied are dropped.

Test-first evidence: the initial remote ops/issues run failed 12 tests, with 75 passing, before implementation. All four requested visibility scenarios failed. Final test and review receipts remain in the operator's scratch directory and the default review store.

A further delimiter regression failed remotely (one failed, 90 passed): a leading Markdown underscore hid an otherwise qualified reference. The strict matcher now treats that underscore as punctuation.

Astra review found URL path normalization and object-key bypasses. Both received failing remote regressions before fixes. Complete GitHub URL tokens now resolve through URL normalization, all property names are checked, and diagnostic paths contain only fixed field names or indices. Host/account redactions no longer hide references from the verdict report.

A second review found credentials introduced by URL decoding and URL destinations hidden across tab/CR/LF. Seven remote regressions failed before the fixes. Every decoded URL reading and final normalized name is now credential-screened. Additional control-normalized URL readings are verified before source redaction; markers are added afterward from checked exact fields, preserving public references at body ends.

Owner-position and encoded credential-context tests then exposed prefix loss during candidate extraction (five failing remote regressions). Discovery now checks all decoded readings of the containing source/token before admitting any substring; sanitized later readings discover only what survives credential redaction.

Five further red regressions cover embedded hostnames and credential prefixes beside underscores (including encoded/case variants and JWTs). Each URL is normalized from its complete suffix before additional references are inspected. Discovery also uses the shared public-content credential check and removes prefixed credentials without a word-boundary assumption.

Eight additional red regressions cover whole URL fields with spaces, GitHub API repository paths, and private-key payloads under canonical, encoded, lowercase, PGP and truncated headers. URL values are validated whole. Private-key regions are removed before any prefix replacement, so payload fragments never become lookup candidates.

Four host regressions failed remotely before fixes. Repository extraction now uses the normalized host and route, including raw/codeload and API URLs; unknown GitHub hosts fail closed.

Two further red regressions cover hostname-shaped repository owners. Strict repository redaction now precedes host/path masking, preserving the complete reference until its verdict is applied.

Four credential-suffix regressions failed remotely before the final discovery change. Credential-bearing original fields are now opaque across all decoded readings, before any destructive substitution. This conservatively omits the whole field from lookup/reporting rather than risking credential fragments in requests or diagnostics. Other fields remain independently discoverable; unconfirmed references still fail closed.

Six credential-property regressions failed remotely before fixes. Discovery preserves decoded property-name context and skips entire credential-named values/subtrees. Publishable records refuse those properties even when the value also appears as a separately confirmed public reference.

Four empty-port URL regressions failed remotely before the matcher accepted the valid empty-port spelling. Both body and complete URL fields now check those destinations, including encoded colon spellings.

Six normalization regressions failed remotely before fixes. Repository URL paths retain trailing dots, complete URL fields lose no punctuation, and explicit private entries share the discovered-reference case/`.git` normalization.

Four complete-destination/source-provenance regressions failed remotely before fixes. Discovery uses original source inputs, never clipped/transformed records that may have lost credential context. Every complete repo destination must itself have a public verdict, including trailing dots.

Nine raw-title/Unicode-host regressions failed remotely before fixes; the ordinary external URL control passed. Drafts are scrubbed before title whitespace normalization or clipping. URL candidates are recognized independently of host spelling and classified after URL host normalization.

The first post-fix run exposed an existing deduplication regression: removing a rejected first draft let a later duplicate through. Rejected originals retain their place in deduplication and carry their original rejection into final validation.

Seven control-split credential/protocol-relative host regressions failed remotely before fixes. Credential screening includes all control-normalized decoded readings before any candidates are extracted. Protocol-relative authorities use the same normalized-host classification as HTTP URLs.

Four written-reference/operator-source regressions failed remotely before fixes. Written and normalized URL paths both require public verdicts. Line-level readings preserve source boundaries. Operator inputs now share pre-transformation validation and retain rejection through deduplication; derived fuzz-area nodes cannot introduce new lookup authority.

Three diagnostics/per-finding regressions failed remotely before fixes. Parser APIs retain their existing formatted default and add an unformatted mode for per-finding validation before formatting. One rejected or closed finding no longer removes unrelated findings. Dropped and duplicate diagnostics use opaque record identifiers and fixed rule/field names, never rejected content.

A further failing remote regression covered the unlinked-queue sidecar. It now screens every row and represents rejected entries only by opaque ID and fixed problem fields/rules.

Six punctuation regressions failed remotely before fixes (one HTTP URL control already passed). Periods and ASCII ellipses now delimit references consistently in discovery and validation, including schemeless URLs and decoded spellings.

Final-review remediation (2026-11-04): GitHub-owned and other code hosts now require repository authority; gists and zero-name code/unknown destinations are denied. Pages require a confirmed repository of the host's owner. All adjacent pairs in written and normalized URL paths, queries and fragments are inspected, including route/ref boundaries. Missing segments cannot become literal `undefined` names. The shared decoder adds NFKC and named slash, period, at-sign and ampersand entities.

Bare prose candidates must stand alone, have valid GitHub syntax, and not be package scopes, filenames, longer paths or lowercase common source roots. Tree destinations and explicit `--repo` targets are confirmed first. Anonymous requests stop at 60 or the first 403/429. Public `private:false` responses alone persist across CLI processes in the caller-owned mode-600 cache with a 24-hour TTL. The mode-checked exact public allowlist never outranks private overrides and its grants are never cached. The private summary includes the request count and every unconfirmed name. Fuzz-link discovery keeps original filenames intact alongside the fixed URL template, before any formatting.

Round 3 (2026-11-04, property-first). Round 2's final review reproduced four failures: query keys went unscanned, Pages checked only its owner, verdict mode switched off the watched-owner rule and rejected dotted names and path suffixes, and a `--private-repos` name leaked under another owner or a path root. `ops/issues/repository-references.property.test.ts` (fast-check, 2,000 runs at fixed seed 20261104; `FC_SEED=random` explores) embeds references from forced-private, 404, unconfirmed, verified-public and allowlisted pools in prose, Markdown, code spans, lists and titles, in bare, URL, Pages, raw, gist, API, Sourcegraph, ssh, fullwidth, percent and entity spellings, nested in another repository's path, ref, query key, query value and fragment. Its oracle decodes the output itself and reads every overlapping `owner/name` pair and Pages host with a broad pattern. On round 2's code it failed within 23 runs; fast-check shrank to, among others, `see sMITHERSAI%2fsECREtrEpo/README.md now`, `https://github.com/roninjin10/notes?a=1&smithersai/secretrepo=2#x`, `https://smithersai.github.io/vibelang/?sTRaNGer/HiDdEn` and `docs/unlisted`; its liveness property failed on `https://github.com/smithersai/vibelang/issues/12`. Each review reproduction is an explicit example too.

Discovery and the scrub now share one decode-then-extract pipeline in `scrub.mjs`: every decoded reading of every token yields primary references (a URL's repository, Pages `<owner>/<name>`, a bare pair that starts a path) and nested ones (other pairs in the path, query and fragment), plus watched-owner and forced-name pairs in any position. A token with any reference not confirmed loses its core and keeps its punctuation, instead of the whole field being refused. Nested names are requested only once a repository around them is public. The importer again refuses to plan without a private list. Repository reads use `githubRead.mjs` when `SMITHERS_GITHUB_READ_TOKEN_FILE` is set; anonymous and App-token requests have separate 60 and 500 budgets. Final ops/issues on cfbox via nyc-01, rebased on main 92e471da: 309 passed, 0 failed; main on the same runner: 108 passed, 0 failed, so no new failing name. The realistic dry plan of the current t3code drafts, read-only with a fresh cache, measured just before that rebase: 21 nodes, 197 issues, 3 rows dropped for private-repo, 60 anonymous requests (the cap), smithersai/vibelang and smithersai/t3code public.

Fable's round-3 review found one remaining class: separators other than a single slash (`smithersai//secretrepo`, `smithersai/./secretrepo`, `docs//secret`). The generator lacked them, though the oracle flagged them. Every reading now also has slash runs, `/./` steps and the fraction and division slashes U+2044 and U+2215 (which NFKC keeps) read as one `/`. The forced-name pattern takes the same run. The generator and oracle cover all of these. The work-links page records the accepted gap: after a path root in a public repository's file path, only watched owners and listed names are read, and an `owner/name` private-list entry makes its owner watched. At 2,000 runs the property took 39 s on cfbox, beyond vitest's 30 s test limit. The default suite now runs 300 (7 s, within a 60 s fast-check limit). `REPOSITORY_PROPERTY_FULL=1` runs 2,000 (300 s limit). Each test's vitest limit sits 30 s past its fast-check limit. Final cfbox: ops/issues 320 passed, and the full property 24 passed.

Compare and pull-head URLs spell a cross-repository ref `owner:name` (`/compare/main...outsider:closed:main`, `?head=outsider:closed`). Each side of a compare spec and each `head`/`base` value is read as the nested reference `owner/name`, so it needs a verdict. The generator has five compare and head shapes. With that reading switched off, the property fails at once on `pulls?head=oUTsidER:CLOsEd.d.GIT`.

Round 4 (Fable's review of b691132e) found bare compare and head specs, pairs split by whitespace, more Unicode slashes, `&colon;`, `..` steps, and too few compare draws at 300 runs. The design changed instead of the list. `reading.mjs` builds readings that keep source offsets. Its normalization reads by property: 57 slash and 33 colon code points from Unicode 15 names and NFKC (`reading-data.py`), and the full HTML5 entity table, where an unknown named reference refuses the field. Whitespace around a slash goes, and dot steps are resolved and also dropped. `clean` redacts by span on the whole field, never by token, and refuses what it cannot map back. Cross-repository `owner:name` is read in bare text as in URLs. A second layer finds known private names as text, with no form parsing. The property generator draws every separator class, colon spelling and compare shape, with a coverage test that each appears at least 20 times in 300 runs. A new noise property embeds known names in random noise and checks no known name survives; with the known-name layer switched off it fails at once on `-acme-internal`. Learned names count only under a watched owner and only qualified: without that rule a 404 for `com/smithersai`, read from inside a URL, redacted `smithersai` everywhere.
Final cfbox run of this round: ops/issues 349 passed, 0 failed. The default property took 3.5 s (60 s limit) and the noise property 1.1 s. The full 2,000-run property took 20.2 s (300 s limit), and all 47 tests passed. Credential screening and readings are memoized, since every reading asks again.

Round 5 (Fable passed round 4 and listed fixes before landing). The readings now also drop combining marks, except the slash overlays, by decomposing, so `smithersaí` reads `smithersai`. They also drop Markdown emphasis and code markers and HTML tags, keeping a word's inner `_` (`node_modules`), so `smithersai/**secretrepo**` and `secret-<b>vault</b>` are read whole. Both changes apply to the text as written and to both decodings. The unknown-named-entity refusal is gone: no renderer decodes an unknown reference and the server escapes `&`, so `AT&T;` and `ptr = &val;` pass literally. A word's `_` before a pair no longer hides it (`x_outsider/closed`), unless the whole word is a path root. The reading cache is bounded at 2,000 texts and about 16 MB. The generator draws emphasis, tags and marks inside names and `_pair` and `x_pair` for every owner, and the oracle reads markers and tags as hard boundaries, or as nothing once unstyled.
Round 5 final cfbox run: ops/issues 358 passed, 0 failed. The default property took 7.6 s (60 s limit) and the noise property 2.1 s. The full 2,000-run property took 44.2 s (300 s limit), and all 55 tests passed.

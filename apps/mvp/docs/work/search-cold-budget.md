Continuing the authorized option: take search input and start its server read before store/service startup, with publication still owned by the existing data gate. Preserve bounded WAL coalescing, transaction grouping and durable acknowledgments. No landing, push or deployment is authorized.

The exclusive browser SQLite VFS now coalesces adjacent WAL fragments in a bounded 64 KiB buffer, preserving FULL sync, file visibility, failure propagation and crash recovery. The real Chromium regression falls from 93 native writes to 3 for one fixed 128-row transaction. Eight buffer cases cover 100% of the new helper; 40 existing SQLite/connection/restore cases and eight real browser cases pass. Final targeted lint and package source/test type checks pass.

Five alternating before/after cold profiles in one remote container measure search at median 5.768 s (5.253–6.171) before and 4.172 s (4.166–4.851) after. All five paired after cases meet the budget without a loading state. Separate initial batches measured 4.677 s (4.207–5.138) before and 4.737 s (4.234–5.290) after. The original volume proof still fails at 5.207 s search, while opening the issue in 691 ms; it also reports the fixture's refs 404. These failures are retained, not excluded to claim acceptance.

Search waits for the worker-backed shared store and application services, including restored chat drafts. In the paired after cases, opening the shared store after activation takes 900–1,008 ms, then services take another 405–504 ms. The separate diagnostic measures 5,576 VFS writes consuming 5.094 s through search completion, with only 794 ms of main-thread long tasks; it does not attribute every write to the pre-render interval.

The startup-independent read and gated publisher meet the original volume proof's search budget across five runs after preserving the outbox's startup independence: 2.865, 3.397, 3.369, 3.349 and 2.927 s (median 3.349 s, range 2.865–3.397 s, spread 0.532 s), against the 8.793 s starting result. Three runs independently report the fixture's existing refs 404; none misses the search budget. The final per-run receipts and full-suite name comparison are in the private report. The existing server-authorized issues client starts before storage, overlapping draft/outbox startup. A publisher is wired before the remaining feature services and follows the existing data gate independently of route loading; the gate may settle after other startup work. Refusal restoration starts before repository metadata and branch conversations but never blocks store construction; its unavailable state still closes the gate. Synced summaries withdraw the early answer. No early result enters a device store, and no cold loading state is introduced.

Failed candidates remain part of the evidence. The first five original runs took 7.062–10.448 s; lifecycle records identified a router history/DOM observer race canceling the early request after 2 ms. A later batch missed once at 5.062 s while refusal restoration competed with unrelated persistence startup. Those regressions are retained. Astra then found a pending-body revocation race; the gate is now observed before joining the body, and an already-claimed revoked cache answer is discarded too. Delayed-response tests fail on the rejected code and pass on the fix, including expiry after consumption followed by gate closure and recovery. Expiry and teardown revoke the claimed entry, and the consumer rechecks generation after joining. No transaction grouping or durable acknowledgment has changed. The full feature run caught direct access to the gate’s raw decision collection; the publisher now uses its public synchronous observer, with independent restoration, revocation and unsubscribe tests. The architecture check stays unchanged apart from printing offending reads on failure. The full comparison also caught an asynchronous store-construction barrier and a reversed outbox dependency: removing that barrier and restoring draft/outbox independence passes all 65 existing draft/run-store and authority/visibility tests. The cold-search regression holds the real role request until early publication, then releases it for normal route handover; this removes its fixed-delay race without substituting server answers. A later, much slower cfbox batch exposed a separate premature handover: the normal list marked a query settled before its gated search answer existed. It now keeps the early slot until that query answers (even with zero rows), sync completes or the view has rows; unit cases cover other repositories, queries, filters and failures. The browser regression retains its strict early-paint assertion and records shell/boot marks on failure. The slow batch is retained alongside all passing timings, and resource sampling accompanies the final isolated browser batch.

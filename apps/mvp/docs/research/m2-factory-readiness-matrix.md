# M2 factory readiness matrix

Audit snapshot 2026-11-25. The eight sibling repositories were checked on the MacBook and Smithers was checked on the Mac mini from a fresh change based on `main` at `b7921914`. Paths in each row are relative to that repository's `.smithers/`. The inventory focuses on factory inputs, entrypoints and release surfaces. It excludes dependency trees, runtime state, caches and run logs. CI descriptions come from the inspected declarations. Targets described by a workspace as living outside `.smithers/` were not run or independently inventoried.

[ADR 0171](../decisions/0171-one-core-four-clients-and-workflows-dir.md) defines the workflow layout. The [M2 plan](../../../../.smithers/plan-tree/M2-factories-playgrounds-upgrades.md) adds home, wiki, plan tree and playground coverage. [WorkflowDiscovery.ts](../../worker/ci/WorkflowDiscovery.ts) looks up `workflows/<name>.vibe`, then `workflows/<name>.ts`, then `flows/<name>/flow.ts`. Invalid preferred entries fail the lookup. TSX and MDX on disk are factory evidence, but neither extension is a candidate in this reader. Nested legacy flow trees need an explicit entrypoint migration. Prove compilation and execution in the runner before publishing a Vibe workflow. The ADR records that the QuickJS planner currently accepts TypeScript-compatible source.

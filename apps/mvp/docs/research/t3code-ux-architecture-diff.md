# T3 Code and Smithers Cloud UX architecture

This review compares the public T3 Code web source and user docs with the M2 Smithers checkout. Start with approval focus and route restoration, then add review and palette improvements to the existing workbench and command surfaces.

| Surface | T3 Code | Smithers Cloud seam |
| --- | --- | --- |
| Threads and panes | The sidebar models grouped threads and attention. Thread jumps operate over the sidebar order. The right panel supports secondary tools and side chats. [Sidebar](https://github.com/pingdotgg/t3code/blob/main/apps/web/src/components/Sidebar.tsx) · [Thread guide](https://github.com/pingdotgg/t3code/blob/main/docs/user/thread-sidebar.md) | [Router](../../src/router.tsx), [conversation list](../../src/features/conversations/components/ConversationList.tsx), and [workbench layout](../../src/features/workbench/layout.ts) already distinguish conversation routing from workbench composition. Use route identity for durable navigation and keyed workbench state for pane selection. |
| Keyboard shortcuts | Typed command IDs and `when` context let a chord mean different things in a pane, editor, or palette. The sidebar ignores handled events, repeat events, and open pickers before thread jumps. [Keybinding contracts](https://github.com/pingdotgg/t3code/blob/main/packages/contracts/src/keybindings.ts) · [Sidebar](https://github.com/pingdotgg/t3code/blob/main/apps/web/src/components/Sidebar.tsx) | [Core button shortcuts](../../src/features/keys/keys.ts), [plugin keys](../../src/plugins/keymap.ts), and [palette binding](../../src/features/commands/paletteShortcuts.ts) each own a listener. Compose precedence across those owners before adding thread or pane chords. |
| Diff review | The Diff panel and PR Code tab support searching across the patch, including collapsed content. Review uses line selections and draft comments. [Keybinding guide](https://github.com/pingdotgg/t3code/blob/main/docs/user/keybindings.md) · [Source-control guide](https://github.com/pingdotgg/t3code/blob/main/docs/user/source-control.md) | [Pull screen](../../src/screens/pulls/PullScreen.tsx), [changed files](../../src/features/pulls/components/ChangedFiles.tsx), and [comparison state](../../src/features/pulls/comparison.ts) provide a first integration point. Store selection against a concrete comparison and file before connecting it to the composer. |
| Approval cards | The composer receives pending requests keyed by request ID. Its typing guard holds requests while drafting and publishes their held state to the timeline. [Chat composer](https://github.com/pingdotgg/t3code/blob/main/apps/web/src/components/chat/ChatComposer.tsx) | [Status queries](../../src/features/status/queries.ts), [plugin action strip](../../src/plugins/strip.ts), and [flow approvals](../../src/flows/approvals.ts) already model waits and person-only decisions. Present a shared request identity so the queue and conversation reflect the same decision and pending state. |
| Command bar | The command palette searches commands, projects, and threads, with an action-only query and direct keyboard selection. [Keybinding guide](https://github.com/pingdotgg/t3code/blob/main/docs/user/keybindings.md) | The [palette](../../src/features/commands/palette.ts) and [composer command catalog](../../src/features/commands/catalog.ts) have separate entry points. Extend palette sources using the existing navigation and plugin contribution paths and keep slash argument completion in the composer. |

## Implementation checklist for Gemini 4 Neon

1. **P0 · Approval identity and focus.** Route a pending approval from the run and queue to the same host-owned decision. Preserve partially typed drafts when the card appears. Keep focus on the current editor until the person opens the card. Test arrival during typing, repeated activation, a changed item version, permission refusal, and a second tab resolving the request.
2. **P0 · Thread and pane restoration.** Anchor the selected conversation in the router and bind pane focus to the workbench selection for that conversation. Test A → B → Back with distinct drafts and pane states. Verify reload on a deep link and a compact viewport with one visible pane.
3. **P1 · Shortcut precedence.** Specify precedence for active modal, palette, focused editor, plugin sequence, and global navigation. Respect editable targets and composition events. Test Ctrl and Meta on their respective platforms and test plugin keys with the queue omitted. Preserve the composer and palette entry chords until a replacement is approved.
4. **P1 · Review navigation.** Start in the PR comparison. Add keyboard file traversal, searchable collapsed hunks, and a line-range handoff anchored to the comparison and file. Test rename, binary file, revision change, and keyboard focus after returning from the composer.
5. **P2 · Palette result sources.** Add conversation and repository navigation through existing actions. Distinguish navigation results from flow dispatch and preserve role filtering. Test collisions between a conversation name and a command, Escape focus restoration, and selections when a plugin is deleted.

Capture before and after Playwright traces or GIFs for a keyboard-only thread switch, a pending decision arriving while drafting, and opening a changed line from an active conversation. Include narrow and desktop viewports.

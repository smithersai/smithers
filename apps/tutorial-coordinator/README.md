# Anonymous live tutorial

The app sends an idempotent operation to the same-origin Worker at `/api/tutorial/live/{research,plan,implement,poc,change}` and polls `/api/tutorial/live/run/:id`. The Worker authenticates an hour-long signed HttpOnly anonymous cookie, applies anonymous request ceilings, and forwards a scoped session to this service with a private bearer token. The service does not accept visitor-supplied model settings, URLs, commands, or repository paths.

Each session/playthrough receives an isolated, credential-free gVisor executor pod. Research runs the actual baseline tests. Planning reads that source and evidence. Implementation requires the latest approved plan ID, asks a genuine Smithers AgentAction to return typed edits, applies only the three allowed example files, and runs protected regression tests. Up to three measured attempts are allowed. A real Git commit is made only after tests pass. POC uses its own disposable executor and never commits to the implementation workspace. Change creates a durable local review artifact from those actual commits; it does not publish a GitHub pull request.

The model action uses `Flow.make`, `AgentAction.make`, QuickJS structured output, and the durable NodeRuntime SQLite store. It has no direct filesystem tools or gateway capabilities. The coordinator performs validated executor operations separately. Model credentials are stored only in the coordinator. Executors receive no secrets or Kubernetes service account token and have no egress.

Every outbound model request and subscription refresh goes through our Cloudflare Worker at `TUTORIAL_PROVIDER_PROXY_URL` (default `https://smithers.sh/api/tutorial/provider`). The shared request executor refuses unmapped destinations rather than sending them directly. The Worker requires the private service token, maps fixed provider route names to fixed upstream HTTPS endpoints, strips internal headers/cookies, refuses redirects, and streams responses without caching. Kubernetes and isolated executor traffic remain internal service calls. The proxy handles ChatGPT/Luna, OpenAI, Gemini, and subscription OAuth refresh; browser requests cannot use it without the server credential. Subscription generation and refresh follow coordinator → Cloudflare → the fixed `/__tutorial/provider/{chatgpt,refresh}` backend relay → OpenAI. The relay uses our existing GKE egress because the subscription endpoint rejects direct Worker egress. It authenticates before reading the body, accepts only the two fixed HTTPS destinations, strips internal authentication/cookies/forwarded headers, refuses redirects, and propagates streamed responses and cancellation. There is no automatic direct fallback around Cloudflare.

Completed service artifacts are removed after two hours; the signed visitor session lasts one hour, and already saved app cards remain local. Expired sessions refuse planning or execution instead of silently starting another repository.

Coordinator request keys and each observed operation result are persisted in SQLite on `/data`. Repeating a request key returns the same run. Approving an already completed plan returns its existing implementation, including with another key. The executor also records a hashed run marker in its Git commit so interrupted commit receipt delivery cannot create another commit. A recreated/expired workspace is detected by its actual base commit and fails explicitly. Each model action has a 32,000-token ceiling (including bounded self-correction), a two-minute wall deadline and at most two retries for interrupted streams, transport failures, or provider 5xx errors with 250/500ms backoff; authentication and credit/quota refusals fail promptly rather than retrying or parking the tutorial. Model steps resume through the durable flow engine. App events show measured starts, completions, failures, model durations/token usage and output corrections, test output, actual files, commits, and patches. The optional agent event sink records only these observations, never private reasoning or credentials; diagnostic JSON files are flushed after the flow transaction exits.

The default model is `gpt-5.6-luna` through ChatGPT subscription authentication (`TUTORIAL_PROVIDER=chatgpt`). `TUTORIAL_CHATGPT_AUTH_FILE` names a writable, persistent Codex auth file. The existing Smithers `CodexAuth` and `OpenAIChatGPT` adapters own refresh, credential redaction, and the subscription request protocol. No API key is used or selected as a fallback. Subscription usage limits still apply.

Production uses a separate server login, provisioned with `codex login --device-auth` in a dedicated `CODEX_HOME` using file credential storage. Supply that login's auth.json path as `TUTORIAL_CHATGPT_AUTH_FILE` to `bun apps/tutorial-executor/infra/deploy.ts <release> --coordinator-only --no-ingress` after tests and bundle build. The deployer sends the file through stdin into the coordinator-only `tutorial-chatgpt-bootstrap` Secret. On first boot, `TUTORIAL_CHATGPT_BOOTSTRAP_FILE` seeds `/data/auth/chatgpt.json` with private permissions. Subsequent boots preserve the refreshed file on the PVC; they never overwrite it with the original bootstrap. Keep this server session separate from desktop sessions, since two hosts must not race the same refresh token. To reauthorize, provision a fresh dedicated login and deliberately replace the server auth file while the coordinator is stopped. Never publish auth files or include them in an image, transcript, executor, or browser payload.

Other configuration: `TUTORIAL_SERVICE_TOKEN`, `TUTORIAL_DATA_DIR` (default `/data`), `PORT` (default 3000), plus executor Kubernetes settings documented alongside `apps/tutorial-executor`. Explicit `openai` or `gemini` provider modes require `TUTORIAL_MODEL` and the corresponding `OPENAI_API_KEY` or `GEMINI_API_KEY` for operator-controlled rollback.

Run `pnpm --filter smithers-tutorial-coordinator test` for bundled Node runtime tests. They exercise the actual durable AgentAction and QuickJS with a scripted provider, bounded structured-output correction, replay, coordinator gates, session isolation, commit idempotency, POC separation, and failed tests preventing commits. Journal and process-restart tests cover rollback, migration, a real SIGKILL, active-owner exclusion, interrupted-run recovery, and explicit retry. These complement the executor's container tests and an authenticated live-provider deployment canary.

Tutorial state is now a projection of the version-1 `tutorial_events` stream. Each run has an ordered hash chain and a `tutorial_heads` watermark. Typed facts record creation, phase changes, step observations, artifacts, and checkpoint results. The existing `run.events` API array remains a *derived step table*: repeated observations of the same step ID replace its displayed status; the underlying journal retains every accepted observation. The `runs.body` and `checkpoints` tables are caches written in the same SQLite transaction as the facts and head. Polling folds the verified stream; boot verifies history and rebuilds deleted or changed caches. Unknown versions, missing history, changed hashes, and stale writer heads fail closed. Pre-journal installations receive an explicit `legacy-baseline` containing only the run/checkpoint state that actually survived, not invented earlier events.

Checkpoint results are acknowledged only after their journal fact and checkpoint cache commit together. This does not make executor effects exactly once: a crash after an external effect and before its receipt leaves that outcome ambiguous. Before any executor or model call, a CAS-committed `execution.claimed` fact binds the run ID to one coordinator owner. A process-lifetime SQLite write lock in `coordinator-owner.sqlite` admits one coordinator for the shared workspace directory, independently of journal transactions. Other instances can observe existing requests but cannot launch work or prune artifacts until the lock is released. The operating system releases it on process death; no heartbeat timeout authorizes takeover. Keep this lock file for the lifetime of the data directory and use `coordinator.close()` when disposing an embedded instance. The existing single-replica, `Recreate` deployment must also be used when upgrading an older coordinator that did not hold this lock.

After acquiring ownership, boot commits an `execution.interrupted` failure for every previously running claim or legacy running baseline, preserving the execution identity, artifacts, and checkpoints. Running steps become failed. The same request key returns that terminal result; an explicit retry creates a new request and still enforces plan/base and commit gates. Unclaimed queued runs can execute. Ambiguous claimed work is never silently replayed or reported successful. A delayed result from a closed owner cannot launch further calls or replace the recovery record. Old binaries fail closed on an unrecognized interruption fact rather than discarding it. The two-hour retention transaction deletes a run's facts, head, and caches together. `coordinator.journal.verify(runId)` checks cache equality against replay without executing work. No credentials or model reasoning are added to this journal; only existing tutorial state and operation result checkpoints are retained.

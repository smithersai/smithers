# Anonymous live tutorial

The app sends an idempotent operation to the same-origin Worker at `/api/tutorial/live/{research,plan,implement,poc,change}` and polls `/api/tutorial/live/run/:id`. The Worker authenticates an hour-long signed HttpOnly anonymous cookie, applies anonymous request ceilings, and forwards a scoped session to this service with a private bearer token. The service does not accept visitor-supplied model settings, URLs, commands, or repository paths.

Each session/playthrough receives an isolated, credential-free gVisor executor pod. Research runs the actual baseline tests. Planning reads that source and evidence. Implementation requires the latest approved plan ID, asks a genuine Smithers AgentAction to return typed edits, applies only the three allowed example files, and runs protected regression tests. Up to three measured attempts are allowed. A real Git commit is made only after tests pass. POC uses its own disposable executor and never commits to the implementation workspace. Change creates a durable local review artifact from those actual commits; it does not publish a GitHub pull request.

The model action uses `Flow.make`, `AgentAction.make`, QuickJS structured output, and the durable NodeRuntime SQLite store. It has no direct filesystem tools or gateway capabilities. The coordinator performs validated executor operations separately. Model credentials exist only in the coordinator. Executors receive no secrets or Kubernetes service account token and have no egress.

Completed service artifacts are removed after two hours; the signed visitor session lasts one hour, and already saved app cards remain local. Expired sessions refuse planning or execution instead of silently starting another repository.

Coordinator request keys and each observed operation result are persisted in SQLite on `/data`. Repeating a request key returns the same run. Approving an already completed plan returns its existing implementation, including with another key. The executor also records a hashed run marker in its Git commit so interrupted commit receipt delivery cannot create another commit. A recreated/expired workspace is detected by its actual base commit and fails explicitly. Each model action has a 32,000-token ceiling (including bounded self-correction), a two-minute wall deadline and at most two retries for interrupted streams, transport failures, or provider 5xx errors with 250/500ms backoff; authentication and credit/quota refusals fail promptly rather than retrying or parking the tutorial. Model steps resume through the durable flow engine. App events show measured starts, completions, failures, model durations/token usage and output corrections, test output, actual files, commits, and patches. The optional agent event sink records only these observations, never private reasoning or credentials; diagnostic JSON files are flushed after the flow transaction exits.

The default model is `gpt-5.6-luna` through ChatGPT subscription authentication (`TUTORIAL_PROVIDER=chatgpt`). `TUTORIAL_CHATGPT_AUTH_FILE` names a writable, persistent Codex auth file. The existing Smithers `CodexAuth` and `OpenAIChatGPT` adapters own refresh, credential redaction, and the subscription request protocol. No API key is used or selected as a fallback. Subscription usage limits still apply.

Production uses a separate server login, provisioned with `codex login --device-auth` in a dedicated `CODEX_HOME` using file credential storage. Supply that login's auth.json path as `TUTORIAL_CHATGPT_AUTH_FILE` to `bun apps/tutorial-executor/infra/deploy.ts <release> --coordinator-only --no-ingress` after tests and bundle build. The deployer sends the file through stdin into the coordinator-only `tutorial-chatgpt-bootstrap` Secret. On first boot, `TUTORIAL_CHATGPT_BOOTSTRAP_FILE` seeds `/data/auth/chatgpt.json` with private permissions. Subsequent boots preserve the refreshed file on the PVC; they never overwrite it with the original bootstrap. Keep this server session separate from desktop sessions, since two hosts must not race the same refresh token. To reauthorize, provision a fresh dedicated login and deliberately replace the server auth file while the coordinator is stopped. Never publish auth files or include them in an image, transcript, executor, or browser payload.

Other configuration: `TUTORIAL_SERVICE_TOKEN`, `TUTORIAL_DATA_DIR` (default `/data`), `PORT` (default 3000), plus executor Kubernetes settings documented alongside `apps/tutorial-executor`. Explicit `openai` or `gemini` provider modes require `TUTORIAL_MODEL` and the corresponding `OPENAI_API_KEY` or `GEMINI_API_KEY` for operator-controlled rollback.

Run `pnpm --filter smithers-tutorial-coordinator test` for bundled Node runtime tests. The first test exercises the actual durable AgentAction and QuickJS with only the provider scripted, checks a bounded structured-output correction, and verifies replay adds no provider calls. The second exercises coordinator gates, session isolation, commit idempotency, POC separation, and failed tests preventing commits. These complement the executor's container tests and an authenticated live-provider deployment canary.

## Mounts

`GatewayServer.layer` mounts seven routes, printed in this order in the startup banner:

| Path | Protocol | RPC group | Authentication |
| --- | --- | --- | --- |
| `/rpc` | HTTP `POST` | `ControlRpcs` | In-band Bearer via `ControlAuth` when configured |
| `/rpc/ws` | WebSocket | `ControlRpcs` (includes `Watch`) | Edge Bearer when configured |
| `/projections` | HTTP `POST` | `GatewayRpcs` (snapshots) | Edge Bearer when configured |
| `/projections/ws` | WebSocket | `GatewayRpcs` (subscriptions) | Edge Bearer when configured |
| `/sync` | HTTP `POST` | `SyncRpcs` | Edge Bearer when configured |
| `/sync/ws` | WebSocket | `SyncRpcs` (stream) | Edge Bearer when configured |
| `/health` | HTTP `GET` | None (workspace identity) | None, by design |

## Bind rules and authentication

The bind policy fails closed:

| Mode | Bind address | Requirements | Startup banner |
| --- | --- | --- | --- |
| **Loopback (default)** | `127.0.0.1:3000` (also `::1`, `localhost`) | No opt-in, no token. `Host` must be loopback; browser `Origin` (if present) must be loopback HTTP(S). Origin-less CLI requests pass. | `auth  no bearer (loopback Host; loopback browser Origin)` |
| **Network** | Any non-loopback address | Requires `--listen` **and** `SMITHERS_TOKEN`. Missing `--listen` refuses with `Refusing to bind <host>: pass --listen to serve on a non-loopback address.` Missing token refuses with `Refusing to bind <host> without a bearer token: set SMITHERS_TOKEN.` | `auth  bearer token` |

- **Plain HTTP only:** `smthrs serve` does not terminate TLS. Put a reverse proxy or encrypted tunnel in front of any non-loopback listener so `SMITHERS_TOKEN` never travels in cleartext.
- **Single principal:** one shared bearer token authenticates every mount. There are no users, roles, scopes, or per-run ownership checks at the gateway layer.

### Why `/rpc` and `/health` differ from edge auth

- `POST /rpc` authenticates in band through `ControlRpcs.ControlAuth`, returning the typed RPC error `Unauthorized` rather than an HTTP edge status.
- `/rpc/ws` stays edge-authenticated because a rejected WebSocket handshake has no RPC channel to carry a typed error.
- `GET /health` is unauthenticated so a local supervisor can identify which workspace owns a port before keeping or replacing the process.

### Ingress and edge refusal codes

The loopback guard runs before every mount (including `/rpc` and `/health`). Edge-authenticated mounts return these HTTP statuses and error codes:

| HTTP status | Code | Cause |
| --- | --- | --- |
| `421` | `invalid_host` | Non-loopback `Host` header on a loopback listener |
| `403` | `invalid_origin` | Non-loopback browser `Origin` header on a loopback listener |
| `401` | `unauthorized` | Missing or wrong bearer token on an edge-authenticated mount |
| `400` | `malformed_request` | Request body contains no valid RPC message |
| `413` | `request_too_large` | Request body exceeds the payload limit (default `1 MiB`) |

## Worker relay status

The routes above belong to `smthrs serve` only. The hosted web Worker no longer proxies raw gateway endpoints:

- `/rpc`, `/projections`, `/sync`, `/health`, and their subpaths return **HTTP `410`** with code `gateway_proxy_removed` (including WebSocket upgrades).
- `GET` or `HEAD` on legacy `/rpc/` documentation paths redirects to this page; RPC-shaped requests still return `410`. Cross-origin calls may fail earlier at the same-origin guard.
- `GATEWAY_UPSTREAM_URL` and `GATEWAY_AUTH_TOKEN` are ignored.

Product web clients use session-authenticated `/api/workflow/provision` and `/api/workflow/rpc`. Each call must specify both a repository and a box (`workspaceId`); the backend resolves that box's coding host by login, repository, and box and enforces a procedure allowlist so host credentials never leave the server. Native RPC or WebSocket clients connect directly to a separately authenticated gateway.

## RPC surface

Source contracts pin procedure names, error vocabularies, and stream frame tags. Row payloads decode dynamically by selector via `GatewaySchema.rowSchemaFor`.

### `ControlRpcs` (`/rpc`, `/rpc/ws`)

Ten procedures govern run execution and operator intervention:

| Group | Procedures | Return type |
| --- | --- | --- |
| **Runs** | `Plan`, `Run`, `Resume`, `Cancel`, `List`, `Watch` | `PlanCard` (`Plan`), `Receipt` (mutations), stream of `ControlEvent` (`Watch`) |
| **Approvals** | `Approve`, `Deny` | `Receipt` |
| **Steering** | `Steer` (durable message), `Signal` (named wait delivery) | `Receipt` |

There is no `Pause` procedure and no memory procedure on `ControlRpcs`; memory is operated through [`smthrs memory`](/docs/reference/cli/memory/).

### `GatewayRpcs` (`/projections`, `/projections/ws`)

Seven read-only projections folded from the control event stream, plus one approval transport mutation:

| Kind | Names | Behavior |
| --- | --- | --- |
| **Read models** | `workspace-runs`, `run-summary`, `run-events`, `transcript`, `run-tree`, `approvals`, `node-output` | Never claim a run and never write state |
| **Stream frames** (`Projection.Subscribe`) | `SnapshotStartFrame`, `RowFrame`, `SnapshotEndFrame`, `DeltaFrame`, `HeartbeatFrame` | Distinguishes initial snapshots from live deltas over WebSocket |
| **Mutation** | `Approval.Submit` | Transport form of Control's approve, deny, and answer commands; adds no new error cases |

### `SyncRpcs` (`/sync`, `/sync/ws`)

Read-only journal replication:

| Procedure | Purpose |
| --- | --- |
| `Sync.Snapshot` | Public projection through a sequence number |
| `Sync.Read` | Paginated journal entries for a scope and cursor set |
| `Sync.Subscribe` | Credit-bounded stream of `Entries` frames |

The native gateway also serves `BranchRpcs` presence at `POST /branch` when its authenticated runtime bridge is configured: `Branch.Announce`, `Branch.Leave`, `Branch.Roster`, and `Branch.PresenceOn`. Branch commands and share-link bootstrap remain unserved on that mount (`Branch.Submit`, `Branch.CreateBranch`, `Branch.MintShare`, and `Branch.WatchRoster` return `unsupported`).

## Health response

`GET /health` returns JSON containing workspace identity only:

| Field | Value |
| --- | --- |
| `workspaceHash` | First 16 hex characters of `SHA-256(resolvedProjectRoot)` |
| `gatewayId` | `cli-<pid>` of the serving process |
| `protocolVersion` | `"1"` |
| `version` | Installed `@smthrs/cli` package version |

No tokens, runs, or filesystem paths are ever included in `/health`.

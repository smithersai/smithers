The common Go backend owns workflow discovery, event matching, durable run admission, sandbox execution, and result publication. A deployment supplies repository storage, sandbox provisioning, and optional GitHub App services. Source support does not establish that these services are configured for every installation.

For the repository's current workflow example, see [Run CI on Smithers Cloud](/docs/guides/cloud-ci/). The local cron library and scheduler are documented separately in [Triggers](/docs/reference/triggers/).

## Dispatch and execution

| Surface | Current behavior |
| --- | --- |
| Definitions | Repository workflows loaded for the event's source commit. |
| Admission | Matching events create durable workflow runs and tasks. |
| Execution plane | Every CI run is created on the sandbox plane. Agent runs use the separate agent plane. |
| Job environment | NixOS VM jobs use the repository's registered closure image or the platform base closure. A repository does not need its own `.smithers/environment.nix` to enter CI. |
| `runs-on` | Workflow metadata; it cannot select another execution plane. |
| Graph checks | A job invokes `smthrs ci <pattern>` to run the `PACKAGE.ts` target graph. |
| GitHub check | `smithers / <workflow name>`, when GitHub App publication is configured. |

The backend's [execution-plane tests](https://github.com/smithersai/smithers/blob/main/packages/backend/internal/services/workflow_run_execution_plane_test.go) cover admission without a repository closure and refusal to select the agent plane through `runs-on`.

## Caches and artifacts

Sandbox jobs receive credentials scoped to their repository, run, and task for workflow cache and artifact operations. Cache restoration and artifact publication belong to the workflow job lifecycle. They are separate from the target graph's action cache and the Flow engine's step cache.

See the [sandbox CI implementation](https://github.com/smithersai/smithers/blob/main/packages/backend/internal/services/workflow_nix_ci.go) and [job credential tests](https://github.com/smithersai/smithers/blob/main/packages/backend/internal/services/workflow_nix_ci_job_credentials_test.go) for the enforced boundaries.

## Completion and GitHub results

The terminal publisher updates the run's commit status and GitHub check run, emits its `workflow_run` event, and dispatches eligible downstream workflows. Publication errors are logged; a successful local run does not prove GitHub received its result.

Inspect the run ID, tested commit, task results, and terminal status, then check the corresponding GitHub result when the repository requires one. Cancellation is distinct from failure. An accepted dispatch, queued task, or in-progress check is not completion.

The owning code is [workflow_run_terminal.go](https://github.com/smithersai/smithers/blob/main/packages/backend/internal/services/workflow_run_terminal.go); its tests cover sandbox-run completion and publication.

## Proposed target automation API

`S.Automation` and `Package.automations` remain a [type-level proposal](https://github.com/smithersai/smithers/blob/main/apps/site/examples/cloud-triggers/contract.d.ts). They are not exported by the current packages. The existing backend workflow service does not make that proposed `PACKAGE.ts` syntax executable.

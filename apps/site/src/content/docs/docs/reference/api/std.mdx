The package exports 33 modules. Import each one as a namespace from the root
entry point:

```ts
import { Read } from "@smthrs/std"
```

Each module also has its own subpath, `@smthrs/std/<Module>`.
`@smthrs/std/internal/*` and `@smthrs/std/<Module>/index` are not public.

Host child processes receive only `PATH`, `HOME`, `USER`, `LANG`, `LC_*`,
`TERM`, `TMPDIR`, and `SHELL` from the Smithers process, plus names explicitly
declared by the caller. Credential-shaped ambient names are withheld; an
explicit declaration is applied last and therefore opts that name in.

For the input and output fields of each flow, see the
[Flow reference](https://github.com/smithersai/smithers/blob/main/packages/smithers/agent/std/docs/reference/flows.md). This page is the module and export
surface.

## Example

```ts
import { NodeServices } from "@effect/platform-node"
import { Read } from "@smthrs/std"

const page = await Effect.runPromise(
  Effect.provide(Read.run({ path: "./README.md", limit: 20 }), NodeServices.layer)
)
console.log(page.content, page.totalLines, page.truncated)
```

A runner declared with `baseline: false` refuses `against: "base"` before

## StdError

The single typed failure every handler uses.

| Export          | Type                                    | Meaning                                                                                                                                       |
| --------------- | --------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| `Code`          | `Schema.Literals` and the matching type | The closed list of failure codes.                                                                                                             |
| `PartialOutput` | `Schema.Struct` and the matching type   | What a command printed before its time limit stopped it: `stdout`, `stderr`, their `Truncated` flags and `DroppedBytes` counts, `mutated?`.   |
| `StdError`      | `Schema.TaggedError` class              | `{ code, message, path?, base_digest?, current_digest?, method?, rpcError?, stderr?, limitMillis?, output? }`, tagged `@smthrs/std/StdError`. |

A `timeout` from `bash` carries `output`: the command's streams up to the
moment it was stopped, cut on the same terms as a finished command's.

```ts
import { StdError } from "@smthrs/std"

const failure = new StdError.StdError({
  code: "not_found",
  message: "File not found: /workspace/missing.ts",
  path: "/workspace/missing.ts"
})
```

The codes are listed in the [Flow reference](https://github.com/smithersai/smithers/blob/main/packages/smithers/agent/std/docs/reference/flows.md#failures).

Every service key, error tag, and class identifier in this package is
`@smthrs/std/<Name>`, so `Effect.catchTag("@smthrs/std/StdError", ...)` catches
every handler failure.

## Probe

Telling an invalid probe from a failing check. A non-zero exit is a runner's
verdict about the code it ran, not about the command it was handed.

| Export             | Type                                                                                         | Meaning                                                                                     |
| ------------------ | -------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| `key`              | `"invalidProbe"`                                                                             | The reserved output key a flow reports one under.                                           |
| `Reason`           | `Schema.Literals` and the matching type                                                      | `unknown-command`, `unknown-test`, `unknown-path`, `unknown-module`, `unknown-environment`. |
| `InvalidProbe`     | `Schema.Struct` and the matching type                                                        | `{ reason, evidence, message }`.                                                            |
| `Attribution`      | `{ to, executed?, invalidProbe? }`                                                           | What one result was attributed to: the tree, or one of the five.                            |
| `CONFIDENCE_FLOOR` | `0.7`                                                                                        | The confidence an attribution needs before it outranks the tree.                            |
| `MAX_OUTPUT_BYTES` | `32768`                                                                                      | The most output bytes one judgment carries, newest kept.                                    |
| `probeAttribution` | `Classifier` `probe/attribution`                                                             | The classifier `classify` asks: `attribution` choice, `executed` boolean.                   |
| `classify`         | `(result: { command, exitCode, output }) => Effect<Attribution, ClassifierError, Evaluator>` | Attributes one command result, with Jev.                                                    |
| `unjudged`         | `(error: ClassifierError) => StdError`                                                       | The standard-flow failure a judge that did not answer is.                                   |

```ts
import { Probe } from "@smthrs/std"

const attribution = yield * Probe.classify({ command: "pytest tests/x.py::nope", exitCode: 4, output })
// { to: "unknown-test", executed: false, invalidProbe: { reason: "unknown-test", ... } }
```

The attribution is Jev's: `classify` asks `probeAttribution`, the exported
`probe/attribution` declaration, through the `Evaluator` service of
[`@smthrs/model`](/docs/reference/api/model/), so a host needs a bound evaluator on a
subscription seat. A zero exit is attributed to the tree without the judge. All non-zero exits,
including 126 and 127, need attribution: a runner can choose those codes after
executing a check. An answer below
`CONFIDENCE_FLOOR` is the tree's failure, which leaves a genuine reproduction
intact. There is no third path: when the judge does not answer, `unjudged`
turns its failure into the caller's typed failure rather than a guess.

The peer that drives the `rg` executable through the permission-aware spawner.

| Export              | Type                                                                                                                              | Meaning                                                            |

argument; those names override the allowlist.

## RemoteSearch

The peer for a tree on another machine, such as a container or a sandbox
machine. It lists the root with the machine's `find`, brings back its
`.gitignore` files and then the files the search reads with `tar`, and lets
`PortableSearch` answer over that copy, so every result, notice, and refusal is
the in-process peer's. Each search is two round trips through the machine's
spawner, whatever the tree's size.

| Export     | Type                                                                                                 | Meaning                                                                      |
| ---------- | ---------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| `maxBytes` | `268_435_456`                                                                                        | The most file content one search brings back; past it, `response_too_large`. |
| `make`     | `(services: Context<ChildProcessSpawner \| Path>, options?: { maxBytes?: number }) => Search.Search` | The spawner runs on the machine; `Path` resolves a relative root there.      |

The machine needs `sh`, `find`, `xargs`, `tar`, `head`, and `base64`; GNU,
BusyBox, and BSD userlands all have them, and a machine without one refuses
with `command_failed` naming it. The program goes in on standard input and
the answer comes back as base64, so a transport whose argv is bounded or whose
output channel carries only text answers intact.

## Container

The host's route into a named container, as an injected transport. Nothing here
spawns: it only decides an argv, which `bash` then spawns through the same
permission-aware spawner as everything else.

| Export         | Type                                                   | Meaning                                                                    |
| -------------- | ------------------------------------------------------ | -------------------------------------------------------------------------- |
| `Container`    | interface and `Context.Service` tag                    | `{ exec: (request: Request) => Effect<Plan, StdError> }`.                  |
| `Request`      | interface                                              | `container`, `file`, `args`, `cwd?`, `env?`, `stdin`.                      |
| `Plan`         | interface                                              | `file`, `args`, `env?`: argv and environment overrides for the host spawn. |
| `make`         | `(service: Container) => Container`                    |                                                                            |
| `unavailable`  | `(container: string) => StdError`                      | The refusal a host with no route answers with.                             |
| `makeNoop`     | `() => Container`                                      | Fails every request with `unavailable`.                                    |
| `layerNoop`    | `Layer<Container>`                                     |                                                                            |
| `makeCommand`  | `(options?: { program?: string }) => Container`        | A `docker exec` compatible CLI. Defaults to `docker`.                      |
| `layerCommand` | `(options?: { program?: string }) => Layer<Container>` |                                                                            |

`makeCommand` attaches `-i` only when the payload arrives on standard input,
because a container CLI holding stdin open for a command that never reads it
makes that command hang. A container name that is empty or starts with `-` is
`invalid_input`, and so is an environment name that is not a POSIX shell name.
A requested variable never reaches the host transport process under its own
name, so `PATH`, `LD_PRELOAD`, or `DOCKER_HOST` cannot choose what runs on the
host: `Plan.env` carries each value as `SMITHERS_CONTAINER_ENV_KEY`, argv
carries only `-e SMITHERS_CONTAINER_ENV_KEY`, and an `sh -c` inside the
container renames it to `KEY` before `exec`ing the program. A request that
carries `env` therefore requires `sh` on the container's `PATH`; an image
without one (distroless, `scratch`) fails every such request, and a request
without `env` runs the program directly. Supply a custom transport for such an
image. Custom transports return any host process environment overrides in
`Plan.env`.

## TreeFingerprint

The identity of one directory tree, measured where the tree is. The host's
workspace walk cannot see a container's filesystem, so `bash` runs this
script before and after a containerised command and reports whether the two
answers differ under the reserved `mutated` key. The harness reads `true` as
a measured write, the way it reads `invalidProbe` as a measured refusal.

Both measurements ride in the transport call that runs the command: `bash`
spawns `sh -c <around> sh <nonce> <deadline-seconds> bash -lc <command>`, so a
containerised command is one round trip. `around` writes the measurements as
the last line of standard error, framed with the call's nonce, and `split`
takes them off before the result is returned. A line framed with any other
nonce, one the command printed itself included, is the command's own output.

The same script enforces the call's deadline inside the container. At the
deadline it sends the command `TERM`, then `KILL` after `graceSeconds`, still
takes the second measurement, and its line says `deadline`, so `bash` fails
with `timeout` carrying everything the command printed. It starts the command
with a GNU-compatible `timeout` where the container has one, else `setsid`,
so the whole process group is stopped; with neither it reaches the command
alone. A POSIX shell starts the command with `SIGINT` and `SIGQUIT` ignored;
GNU `env` puts them back where the container has it. The host's own clock is
a backstop at the deadline plus `overrunSeconds` and one transport round trip.

| Export                  | Type                                                                       | Meaning                                                                                                                                        |
| ----------------------- | -------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| `key`                   | `"mutated"`                                                                | The reserved output key a flow reports a measured write under.                                                                                 |
| `defaultPrune`          | `ReadonlyArray<string>`                                                    | Directory names never descended into: every name the search walk skips, including both scratch checkout directories, plus `venv` and `target`. |
| `defaultIgnoreSuffixes` | `ReadonlyArray<string>`                                                    | Name suffixes left out, compiled output above all.                                                                                             |
| `maxPaths`              | `50000`                                                                    | The bound past which a listing is a prefix and reports `complete: false`.                                                                      |
| `Measurement`           | interface                                                                  | `{ digest, paths, complete }`.                                                                                                                 |
| `script`                | `(options?: { prune?, ignoreSuffixes? }) => string`                        | The POSIX shell script: sorted `find` + `stat -c` listing, `cksum`, count.                                                                     |
| `parse`                 | `(stdout: string) => Measurement \| undefined`                             | Reads one measurement; anything malformed is unmeasured, never unchanged.                                                                      |
| `moved`                 | `(before?, after?) => boolean \| undefined`                                | `true`/`false` from two complete measurements; `undefined` from anything less.                                                                 |
| `marker`                | `"__smithers_tree__"`                                                      | The word `around` starts its line of standard error with.                                                                                      |
| `measureSeconds`        | `60`                                                                       | How long one measurement inside `around` may take; a longer one is unmeasured.                                                                 |
| `graceSeconds`          | `2`                                                                        | How long a command stopped at its deadline has between `TERM` and `KILL`.                                                                      |
| `overrunSeconds`        | `122`                                                                      | The most `around` adds to its command's deadline: two measurements and the grace.                                                              |
| `nonce`                 | `Effect<string>`                                                           | Sixteen fresh hex digits that frame one call's line.                                                                                           |
| `deadlineSeconds`       | `(limitMillis: number) => number`                                          | A deadline in whole seconds, rounded up, at least one.                                                                                         |
| `around`                | `(options?: { prune?, ignoreSuffixes? }) => string`                        | The POSIX shell script that measures, runs `"$@"` under the deadline with its own stdin and streams, measures again and exits with its status. |
| `split`                 | `(stderr: string, nonce: string) => { stderr, before?, after?, timedOut }` | Separates the call's last line from the command's standard error; standard error without it is returned whole, unmeasured.                     |

Identity, not content: size and mtime per file, so a rewrite that restores
both is invisible, exactly as it is to the host walk. Every tool the script
needs is POSIX or busybox; a container without `find`, `stat -c` or `timeout`
is unmeasured and `bash` reports no `mutated` at all. A tree with no file in
it is a measurement, so the first write into an empty directory is a move.

Process timeout overrides for `bash`, `shell_command`, and `test` must be finite milliseconds greater than zero and at most 600,000. An invocation’s `timeoutMs` overrides `Runner.timeoutMs`. When the invocation omits it, the host default is checked instead; an invalid selected value fails with `invalid_input` before spawning.

`capture(id)` returns a `Snapshot`. `materialize(id, use)` is scoped: it hands
the tree to `use` and removes the checkout however that effect ends. Host git
never runs with the workspace's `.git` as its `GIT_DIR`: it records and checks
out through a temporary shadow repository that shares only the workspace's
objects, with host config files switched off. The shadow directory has mode
`0700` before workspace data is staged, so other local users cannot read its
checkpoint or baseline tree. A hook, `core.fsmonitor` command,
filter driver or `info/attributes` entry written into the workspace's `.git`
therefore does not run on the host. The workspace is still read for refs, its
index, its config file (as a file) and a few `core.*` hashing settings. A
checkout gets its own standalone `.git`, so a container can run git in it.

A materialize never has host git write into an agent-writable directory. It
writes the checkout and its `.git` into a staging directory the agent cannot
reach, inside the temporary shadow or, when the host's temporary directory is
another filesystem, a `.smithers-checkout-<uuid>` directory beside the
workspace root, or `checkout-<uuid>` under `$XDG_CACHE_HOME/smithers` (default
`~/.cache/smithers`) when the root's parent is not writable. One `rename` then
gives the finished directory its name under the workspace. A checkout name the
agent swaps for a symlink fails the call before anything is written through
it. The rename runs from inside the checkout's parent, entered by its physical
path, and a parent that resolves outside the workspace root's real path fails
the call before the rename. When no staging directory shares the checkout's
filesystem, the materialize is refused rather than copied, and the refusal
names each candidate, including a root parent that is not writable.

Two data-write residuals remain, neither of which runs a program. First, host
writes into agent-writable `.git` paths (new objects, the checkpoint's config
entry) follow a symlink the agent races into place. Second, the repository is
whatever `git rev-parse --git-common-dir` names: a `.git` gitfile
(`gitdir: <path>`) or an `objects/info/alternates` entry can point it at
another git directory on the host. Captures then write objects and the config
entry into that directory, a checkpoint id edited in `.git/config` can name a
commit from it, and read-tree resolves object ids across the alternate store,
so a materialize can write another host repository's files into the checkout.
Both residuals apply whenever the agent can write the workspace, including its
`.git` through a container bind mount; creating `.git` in the harness does not
help, because the agent can rewrite it afterwards. The only mitigation is a
`.git` and checkout path the agent cannot write, such as a read-only mount of
`.git`, or running captures and checkouts against a git directory the harness
keeps outside the mount.

## Relocate

What can be pointed at a checkpoint, and what cannot.

| Export       | Type                                                                    | Meaning                                                        |
| ------------ | ----------------------------------------------------------------------- | -------------------------------------------------------------- |
| `Relocation` | tagged union                                                            | `Relocated`, `UnsupportedFlow`, `AbsolutePath`, `OutsideTree`. |
| `relocate`   | `(flow: string, input: Json, materialized: Materialized) => Relocation` | Rewrites one call's input onto a checkpoint.                   |

`relocate` knows the field each supported flow names a location in: `cwd` for
`bash`, `path` for `read` and `ls`, `root` for `grep` and `glob`. Every other
flow answers `UnsupportedFlow`. Both names are re-exported from `Checkpoints`,
which is how the harness reaches them.

## LanguageServer

The code-intelligence seam.

| Export           | Type                                          | Meaning                                                             |
| ---------------- | --------------------------------------------- | ------------------------------------------------------------------- |
| `Position`       | interface                                     | `path`, `line`, `character`, in the protocol's 0-based coordinates. |
| `LanguageServer` | interface and `Context.Service` tag           | Ten queries, `sync`, `close`, and `refresh`.                        |
| `make`           | `(service: LanguageServer) => LanguageServer` |                                                                     |
| `makeNoop`       | `() => LanguageServer`                        | Answers `unsupported` for every request.                            |
| `layerNoop`      | `Layer<LanguageServer>`                       |                                                                     |

The queries are `hover`, `definition`, `references`, `implementation`,
`documentSymbols`, `workspaceSymbols`, `prepareCallHierarchy`,
`callHierarchyIncoming`, `callHierarchyOutgoing`, and `diagnostics`, each
returning `Effect<unknown, StdError>`. `sync(path, text)` sends a file's new
text, `close(path)` says it is gone, and `refresh` re-reads every synced file
from disk, resending changed ones and closing deleted ones.

`NodeLanguageServer` in [`@smthrs/platform-node`](/docs/reference/api/platform-node/) binds this
service to language-server processes on the host. See
[Query a language server](https://github.com/smithersai/smithers/blob/main/packages/smithers/agent/std/docs/guides/query-a-language-server.md).

## Runtime notes

The root entry point is platform-neutral. It imports and runs in a browser, a
Cloudflare Worker, Node.js, and Bun, and it reaches no `node:*` module. A
handler that needs the machine gets it from a host layer:

| Need             | Where it comes from                                                                                                                   |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| Files and paths  | `FileSystem` and `Path`                                                                                                               |
| Processes        | `ChildProcessSpawner`, with the environment read through [`@smthrs/kernel`](/docs/reference/api/kernel/)'s `ChildProcessSpawner.ambientEnvironment()` |
| Web destinations | an `HttpClient` that implements the kernel's destination pinning, and the kernel's `HttpClient.ResolveHost`                           |
| Language servers | `LanguageServer`, bound on Node.js and Bun by `NodeLanguageServer` from [`@smthrs/platform-node`](/docs/reference/api/platform-node/)                 |

`HttpClient.ResolveHost` refuses every name by default.
[Reach the network](https://github.com/smithersai/smithers/blob/main/packages/smithers/agent/std/docs/guides/reach-the-network.md#where-names-resolve) covers
which hosts resolve names and what the web tools return where none does.

The model behind this surface has its own pages:

- [Limits are disclosed, never silent](https://github.com/smithersai/smithers/blob/main/packages/smithers/agent/std/docs/concepts/limits-and-disclosure.md) for
  every cap and how it is reported.
- [Effects and capabilities](https://github.com/smithersai/smithers/blob/main/packages/smithers/agent/std/docs/concepts/effects-and-capabilities.md) for the
  declared envelopes, the narrowing, and why hermetic mode is a pre-check rather
  than a sandbox.

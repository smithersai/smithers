**History** opens the repository's **mythical history**: a narrative of how the code fits together, organized into smaller changes. It is separate from the list of flow runs.

## Open History

Select **History** in the sidebar. Read the history returned for the repository, or the empty-state explanation when none exists.

<AppScreenshot src="/images/app/history.png" alt="The History card explains that the Smithers repository has no mythical history to show." caption="An empty History card means there is no mythical history to display. It does not imply that the repository has no Git commits." />

Opening History reads the available history. Its **Create** action asks the server to bootstrap the repository's mythical stack from main. Sign-in and repository permission are required. Follow the background toast until the stack is active; a request acknowledgment is not a completed bootstrap.

## Inspect the live Stack

Run `/stack.show` for the selected repository, or `/stack.show owner/repo`. The Stack card shows issue work, active lanes, checks, failures, and pull requests. A lane can include elapsed time, the account, and the model seat reported by the server. Open the associated run or pull request to inspect its evidence.

Repository administrators can use `/stack.backfill` to admit open issues, `/stack.parallel` to set one to eight lanes, and `/stack.retry` to retry a blocked, rejected, or declined item. These actions run in the background and report their results through the shared toast stack.

Only the stack service writes `mythical`. For repositories configured to send work upstream, the owner merges the GitHub pull request; main remains append-only, with one commit per item. A ready stack item or open pull request is not a landed change.

## Find a different kind of history

Use the view that matches what you need to inspect:

| Question | Where to look |
| --- | --- |
| What did a flow do? | [Runs](/docs/app/runs/) and the run trace. |
| What changed between revisions? | [The Change card](/docs/app/changes/) and its revision comparisons. |
| What commits exist in the source repository? | The repository's GitHub history. |
| Which issues are being planned, implemented, or checked? | `/stack.show` and its linked runs. |
| How is the code explained through mythical history? | **History**, when the repository provides it. |

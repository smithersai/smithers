# 0021. The project wiki in the conversation

**Status:** accepted, 2026-11-07. **Rulings:** VL-4, VL-5, VL-8, VL-9, VL-11, VL-13, VL-17, VL-23, VL-27, VL-29; FLOW-3.

**Decision.** The wiki is a maximizable pane in the conversation. Wiki in the top bar, its page links, a browser
address and the agent's `vibelang/wiki/open` all reach the same durable flow and the same numbered `PaneOpened`
event as decision 0014's docs. A person opens with an empty entry id; an agent tool captures its own streaming reply
id, so a stale agent cannot move the pane. `decide`, `apply` and `receive` remain the only conversation machine.
The existing docs maximize state and Escape path control both panes. An agent-opened wiki appears between its
person's post and its answer. Page changes preserve that position. Reconnect replays the same pane events.

**Build and links.** `scripts/wiki.vibe` reads every wiki Markdown file before dev, build, typecheck, tests, plan and deploy and
uses chat's `src/web/markdown.vibe` renderer to produce escaped HTML in an ignored build module. Headings, lists,
quotes, tables, links, strong text and code use the shared renderer; arbitrary Markdown HTML remains text and
executable link schemes are refused. There is no new dependency. `/wiki/index`, `/wiki/rulings`, `/wiki/roadmap`,
`/wiki/decisions/<number>-<slug>` and `/wiki/designs/index` are stable addresses. Relative Markdown links resolve
against their source file. Generation precedes Alchemy importing the API, and the generated source participates in its build cache inputs. The site Worker runs before static assets and serves the application shell only for known wiki addresses, the landed History entry and home. Real workerd asset-binding tests guard deep links and reject unknown/fault paths before SPA fallback. The pane
owns browser back/forward navigation, including ruling anchors. The mock embeds these same current pages, with
no backend, model or requests for wiki content.

**Design.** The handoff is copied verbatim to `wiki/designs/wiki/{index.html,NOTES.md,LEAD-NOTES.md}`. It supplies
pane chrome, the 188px page list, local filter, breadcrumbs, decision status/date/ruling chips, the horizontal
phone page row and maximize icons. The lead's overlap correction keeps the whole pane above the composer. The
index reads the actual ruling range, including VL-29, instead of the design's old VL-28 copy.

**Where rulings win over the prototype.** VL-27 keeps every wiki state dark. VL-23 makes repository Markdown the
working memory: the prototype's sample page bodies and decision metadata are replaced with the actual deployed
source. VL-5 adds no Markdown or routing package. VL-8 and VL-11 require even a person's page navigation to use the
sequencer and durable flow, rather than swapping prototype screens locally. VL-21 and decision 0019 require real
identity and policy: until the roles lane supplies the role interface and authorized editing flow, every role is
read-only and Edit/Save/Propose do not appear. No pretend save or unreviewed contributor write is shipped.

Loading and errors stay within the pane. Loading disables maximize; a failed opening offers Retry without stopping
chat. Search is local view state. The flow logs `vibelang.wiki.open`, spans it and increments
`vibelang_wiki_steps{outcome}`; only outcomes are recorded, never page paths, Markdown or user text. The HTTP
boundary also uses the existing request spans/counts. The engine journals every opening step.

**Validation.** Tests were written and run failing first for scene and browser entry, pane opening, navigation,
maximizing, deep links and agent opening. Unit/integration cases exercise replay, invalid pages and stale actors,
shared rendering and redacted observability. Browser cases use the product mock in desktop dark, light-preferring
(still dark) and phone projects, without request interception. The conversation contracts and executable mutations
cover the person-opening extension as well as the existing agent guard. Exact commands, counts and screenshots
are retained in the lane report; the lead deploys and runs the deployment acceptance check.

**Review regressions.** Opening a wiki after a long conversation pauses transcript following and scrolls the whole
pane clear of the composer. Back to home restores the splash; Forward uses the opening flow. Switching conversations
clears an old agent pane position, and person openings validate any retained position against current entries.
Home can return to a retained wiki through its minimize button or Escape before any post exists; the shared screen
policy includes pane content, with contracts and mutations. An HTTP acknowledgement cannot finish loading before the numbered event, and an older failed request cannot replace
a newer page. Each has a retained model/scene or browser regression.

**Parallel feature navigation.** History landed while this lane was validating. Its header link remains beside Wiki.
On a phone the header's links scroll within the available width, preserving every landed control without page
horizontal overflow. Keyboard tests traverse the rendered header controls rather than assuming a fixed number.

**Tour integration.** The tour lane moved maximized panes outside the inactive transcript. Wiki uses that same
slot, preserving its native content and usable maximize/minimize controls. The ordinary reply exposes
`vibelang/docs/open` beside `vibelang/wiki/open`, both with its captured actor. The tour narration agent stays
tool-free; its durable controller retains page order and reading time (0014).

Error and loading panes also occupy the maximized slot before a page commits. A numbered docs opening supersedes
stale wiki loading/errors, so Retry failures cannot hide the tour. While the tour owns a wiki pane, it stays
maximized and uses the tour's global Escape control, matching docs; minimizing returns with control.

The complete header fits at 390px using 13px links, 4px inline padding and 4px icon gaps. The navigation retains
its internal scroll fallback at narrower widths. This preserves the landed History/header regression without
hiding any control or adding a second phone navigation pattern.

The wiki content and page list own their native keyboard scrolling. The conversation's causal Home/PageUp handler
leaves nested scroll surfaces to the browser, so those keys cannot move the background chat while reading a page.

The parallel Sandboxes pane is retained in the conversation. Opening a wiki page brings it to the foreground by
minimizing a maximized sandbox; the sandbox and its work keep running. Both requests and numbered pane events
apply this view policy. Terminal output also retains native keyboard scrolling through the shared scroll-surface marker.

The reverse handoff is also explicit: a sandbox command from a maximized wiki releases the docs/wiki slot and
shows the sandbox maximized, so progress, errors and Stop remain visible. It uses the same existing sandbox flow.

Minimizing also reveals the inline wiki above the composer after the Sandbox card changes transcript height,
without changing the address or explicitly resetting content scroll. A `/sandbox` submission closes the native Ask dialog through the same
close/focus command as ordinary submissions. Browser regressions cover both native DOM boundaries.

Main's frozen dependency graph can install multiple Vitest peer contexts. The app uses the monorepo fuzz package's
existing Vite configuration: inline the Effect test adapter and resolve its Vitest import to the app's runner. A
clean forced frozen install reproduced the missing-suite failure before this configuration; the scene suite and
full checks validate the repair. The source-coverage child fixture uses the same configuration, so it fails only
for its deliberately unvisited branch. No dependency or coverage threshold changes.

Native-scroll browser assertions use causal boundaries: touch compares to the first actual move and waits for
post-end scrollend; keyboard Home follows a completed End scroll with focus still in the wiki. These waits
retain the direction, pause, completion, Latest and viewport assertions instead of measuring an earlier sample.

The marketing-media lane's shared-pane update is retained: media sources reach startup flags, docs keep their
media/narration layout, and ordinary empty chats keep the compiler artwork. A visible wiki counts as content,
so that empty-chat artwork is absent while reading the wiki. A fail-first scene and browser assertion cover it.
All lane ports share the selected E2E_PORT, including the media and review lanes' aliases.

The roles pane shares the same foreground: opening the wiki demotes a maximized People list to its pane, and
opening People from a maximized wiki gives People the maximized slot and the wiki the pane. One maximized
surface at a time; nothing closes. Fail-first scene cases cover both directions.

On phone the maximized wiki clears the wrapped header through the shared --vl-header-height custom property
rather than a fixed inset, so the pane begins below the banner in mock and live layouts alike; a browser
assertion measures the pane against the banner's actual box.

The issues lane landed in parallel: fault names, e2e port aliases, the faulty-factory shape and the navigation
keep both lanes' entries, and the chat view renders the issues overlay, the wiki pane and the docs pane through
the same showsWiki/pane conditions.

## Editing by role (lane vl-wikiedit, 2026-11-09)

The designed `edit-maintainer` and `propose-contributor` screens now run in this pane. Contributor and Maintainer
see Edit; Viewer, New and Community do not. Cancel and Escape discard an unsubmitted edit. The maintainer's button
reads Save; the contributor's reads Propose. **Both create the person's own review change.** The design's direct-save
note yields to the human review boundary: neither operation changes main or merges. A successful submission links
Review and keeps the repository page unchanged. A submitted write remains recoverable until it settles; uncertain
outcomes retain the exact request and key, and Retry uses the engine's native `retryFrom`. A known write-free refusal
releases the text for correction. Late responses cannot close another page's editor or cross a person/role change.

The actual embedded source is **`smithersai/smithers`, `apps/vibelang/wiki/*.md`**, rather than VibeLang's separate
issue repository. The generated Decisions index is read-only. Live reads use that repository's Markdown and blob
revision. Source validation also reads the exact commit on which a proposed branch will start, preventing an edit
from overwriting a page that advanced between observations. The default repository/root and optional test base
branch are host configuration, never request fields. The bounded HTTP body accommodates the actual largest page
(the proofs inventory); current edits and their base share a 4 MiB request budget and a three-second body deadline.

`Factory.wiki`, CLI/MCP `wiki`, and `vibelang/wiki/{read,draft,save,propose}` share the same durable flows. Policy
maps public reading to `read`, draft/propose to the new Contributor-minimum `wiki` permission, and Save to the existing
Maintainer minimum. The host rechecks current grants and immutable identity before each external operation, even
when joining a cached receipt. Only a person submits; a privileged agent principal still cannot save or propose.
The live chat binding delegates only draft, captures the accepted post's owner, and returns a Review it link. A
schema-checked `AgentAction` uses the existing model host and metered token budget. The person opens its retained
draft in the editor and submits explicitly. Drafting neither creates a branch nor writes repository Markdown.

The library catalog's GitHub implementation is **`@smthrs/integrations`**: `Proposals.ensureFork`, `Once.branch`,
`Once.commitOnBranch`, `Once.pull` and `Proposals.documentReview`, called through `Action.once`. The branch belongs
to the person's fork (or their own upstream repository), the commit fences its exact head, and the PR's immutable
author and complete single-file change set are observed before reporting success. No second GitHub client, proposal
adapter, authentication implementation, retry loop or merge operation is added. 0019/0022's explicit encrypted
session credential connection is reused; credentials never enter requests, flow payloads, results or telemetry.
Unconnected submissions retain their reviewed Markdown privately before Connect GitHub; the validated OAuth return
stays on that wiki page. Submitted drafts are cleared only when they match the submitted text.
Connecting GitHub for writes is decided in smithers.sh's `apps/mvp/docs/decisions/0165-hosted-site-github-delegation.md`.

Mock mode has one shared fixture repository, private drafts and per-person durable engines using the real flows.
It needs no backend or model. Save and Propose add a review receipt without changing the source. Role changes are
resolved at execution, including a queued chat draft. The real workerd suite uses persistent SQLite journals.
Logs, spans and counters record operation/outcome only; tests exclude page, Markdown, prompt and request key.

Tests retained failing-first receipts for scene/role/ordering behavior, source routing, in-flight/retry safety,
HTTP replay, maximum page size, person-only submission, generated links/cold generation, and draft cleanup.
The independent fuzz target exercises role/draft/submit/replay sequences; the benchmark measures both complete
fixture edit journeys with assertions and explicit network/model exclusions. These are no claim of whole-app
100% coverage. The changed projection, policy, routing and editor-identity contracts are proved, with executable
unchanged-contract mutations. Network execution, provider identity and browser layout remain tested host boundaries.
`GITHUB_TEST_TOKEN` enables the real test on `roninjin10/smithers-github-tests`: temporary base branch, actual wiki
Markdown, both role submissions, fenced commits, author/file observations, replay and unchanged base; PRs close
without merging and only the test's branches are removed. Without the token it is explicitly skipped.
No dependency is added. The report retains exact commands, counts, exits and desktop/phone screenshots. Lead deploys.

# Build the flow they asked for

You are the authoring pipeline for a new Smithers flow. The request is appended
below. Your job is a flow that exists on disk and verifies, not a plan for one.

The six stage instructions are included below. Work through them in order,
carrying each stage's result into the next. Do not skip a stage because the
request looks small. The stage names label sections of this task; complete
them here without calling another flow.

| Stage | Result |
| --- | --- |
| 1. Clarify | A precise specification, and whether this needs a flow at all |
| 2. Provision | The docs, the closest example, and the patterns that fit |
| 3. Design | The node graph to approve |
| 4. Scaffold | The files to write |
| 5. Fix | Repairs until verification passes |
| 6. Document | The skill file future agents read |

For stage 1 use the request appended below. For later stages use your findings
from earlier stages and this project's directories.

## The two stages that are not optional

**Stop after Design and call `ask`.** Put the goal, name, stages,
loops, human gates, and every clarifying question with its proposed assumption
in the `question`. Wait for the answer. If `approved` is false, stop without
writing files. Continue to Scaffold only after approval. A flow
written from an unapproved design is work they did not ask for, and the clarify
stage promises them this gate by name.

**Do not finish until Fix has nothing left to do.** Run the
project's typecheck, `smthrs ls`, `smthrs plan <flowName>`, and the flow's own
test. If any fails, apply the Fix instructions below using the exact command,
its exact output, and the design, then run the checks again. Repeat until they
pass or until you have tried four times.

## When clarify says `direct`

Stage 1 decides whether this needs a flow at all. If it answers `direct`, stop
there. Tell the person the one-line thing to do instead and why a flow would
cost more than it saves. Write no files. That is a successful run.

## What to report

Report only what you actually did:

1. The flow's name and the path of every file you wrote.
2. Each verification command, and whether it passed.
3. The skill file's path.
4. One line naming the single next thing the person should do.

Never report a file you did not write or a command whose output you did not
read. A half-finished flow named honestly is worth more than a finished one
described from memory.

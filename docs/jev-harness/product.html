Jev Harness: Product

Draft 1, 2026-09-17. Owner: Will. This doc says what we ship, for whom, why they pay attention, and how we will know it worked.

One sentence. Smithers becomes a coding agent you run in OpenCode's UI, whose loop can make hundreds of cheap typed decisions per task with Jev, and which tells you at a glance whether it is on track.

One paragraph. A developer starts smithers opencode in a repository, opens app.opencode.ai, and gets the OpenCode session view they already know, backed by the Smithers cell loop instead of OpenCode's. Inside that loop the agent writes JavaScript cells and reaches the world only through ctx.call. We add one new door, classify, that asks Jev typed questions about any state the cell holds: is this file relevant, which of these commands is the check, did that run fail for the right reason, how risky is this edit. A Jev answer costs about a thirtieth of a cent and lands in about 300 ms, so the agent can judge every file in a directory inside one cell instead of spending a model turn per judgment. The same Jev call watches the run from the outside: after every frame it scores progress and flags stuck or needs-a-human, and the session title carries a green, yellow, or red dot the user reads from across the room. No new UI is built. The product is the harness plus the door plus the dot.

2. Why it is useful

Three claims, each falsifiable on day one.

  1. The agent judges more and spends less. Today a judgment costs a model turn: read ten files, print them, decide next frame. With classify the cell asks Jev about all ten in one call and branches in the same cell. Test: on a task that touches a directory of files, count frames and dollars with and without classify. The claim fails if frames do not drop.
  2. You know when to look. Jev scores every frame on progress, stuck, and needs-a-human. Test: over a day of sessions, count the times the dot went red or yellow and Will agreed on inspection, versus the times it stayed green while the run was stuck. The claim fails if the dot misses stalls the discipline caps already catch, or cries wolf more than once in five.
  3. Zero UI to learn, zero UI to build. OpenCode's app renders sessions, tool calls, diffs, permissions, and cost. Test: Will completes a real task end to end without leaving the OpenCode UI. The claim fails if any step needs the terminal.

4. Non-goals for this release

  • No new UI, no fork of the OpenCode app, no theme work.
  • No custom UI. The hosted app and opencode attach both use the implemented v1 protocol. TUI fork, compact, revert, shell and session-command features are outside this release.
  • No multi-user, no auth beyond OpenCode's basic password, no remote hosting.
  • No OpenCode agents, skills, MCP, LSP, PTY, or worktree features. The routes answer empty.
  • No Jev authority over destructive actions. Jev ranks, gates, and reports; permissions and completion checks stay with the harness and the person.
  • No changes to the product app in apps/app or the cloud worker.

5. Strategy

  • Borrow the surface, own the loop. OpenCode's app is the best-maintained agent UI available and it speaks a documented HTTP contract. We implement that contract over the Smithers cell loop. The surface stays theirs; the durability, discipline, and Jev stay ours.
  • Jev is the agent's cheap sense. A cell loop already thinks in code. Giving the code a typed judgment call turns file lists, command outputs, and diffs into decisions without a model turn. This is the feature no other harness has today.
  • One new core API. Classifier is the only addition to the Smithers libraries. Everything else is a server package and a flow binding.
  • Launch by using it. Will runs it for a day. The three claims above are scored from that day. The doc is updated with the numbers before anyone else is shown it.

6. Evidence and risk

Demand evidence today is one person's workflow dependence: Will's. No external user has asked for Jev inside a harness. The day-one run is the demand test, not a launch celebration. If Will does not reach for the OpenCode UI on day two, the surface bet failed and the harness work still stands on its own.
  • Jev accuracy is vendor-reported. TypeSafe's own dashboard puts Jev below frontier reference labels on every listed task. We treat every answer as ranked evidence gated on confidence, never as a verdict. The health dot is advisory; the discipline caps remain the enforcement.
  • The hosted app moves under us. app.opencode.ai tracks OpenCode main. We verify the contract against the recorded 1.18.31 trace and its OpenAPI schemas. A pinned, locally served app fallback has not shipped.
  • Protocol v1 is the shipping contract. The app reads /global/event; the TUI reads the bare payload on /event. Three compatibility routes also answer: /api/health, /api/session, and /api/reference. See the live trace.

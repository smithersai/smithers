Jev Harness: Research

Living document. Started 2026-09-17. Append new findings to the log at the bottom with a date and a source. Every claim here names where it was read.

Summary. Three bodies of fact drive the design: what Jev is and how we already call it, how the Smithers cell loop works today, and what the OpenCode app needs from a server so it can be our UI. All three are verified against primary sources on 2026-09-17: TypeSafe and Vercel docs, the Smithers source under packages/smithers/agent, and a fresh clone of OpenCode main plus the installed CLI 1.18.31.

1. Jev

Jev is TypeSafe AI's decision-only model. One request carries a state and a map of typed questions; the answer is one typed value per question with a probability distribution and a confidence. It generates no text, so it cannot invent an option the question did not offer, and every question in a request is answered in parallel.

1.1 Wire protocol we use

Vercel documents the evaluation modality as "AI SDK only", but the SDK's gateway provider is open source and speaks plain HTTP. Our client copies its protocol and carries no ai dependency and no TypeSafe key. This is landed and live in apps/server/src/jev.ts.

POST https://ai-gateway.vercel.sh/v4/ai/evaluation-model
authorization: Bearer $AI_GATEWAY_API_KEY
ai-gateway-protocol-version: 0.0.1
ai-gateway-auth-method: api-key
ai-evaluation-model-specification-version: 4
ai-model-id: typesafe-ai/jev
content-type: application/json

{ "state": ..., "questions": { ... }, "providerOptions": { "gateway": { "zeroDataRetention": true } } }

200 → { "answers": { "<questionId>": { "type": "choice", "choice": "...", "probabilities": {...} } , ... } }

The contract is undocumented, so every call site falls back on any non-200 or unreadable body. Probabilities round to two decimals.

1.2 Where Smithers already uses Jev

  • Command recommender, apps/server/src/recommend.ts: one choice question whose options are every runnable command; probabilities order the pills; Cerebras is the fallback. Live on prod since 2026-09-17; the Worker secret AI_GATEWAY_API_KEY is present.
  • Session health checker, packages/smithers/control/src/JevSessionChecker.ts: state is the lifecycle plus the last 4 KiB of terminal output; answers working, idle, or needs-input; confidence floor 0.7; degrades to the lifecycle answer. Bound by the app's bun host for terminal and agent subjects when the key is set.

2. The Smithers harness today

The agent is @smthrs/agent at packages/smithers/agent: one Effect service, Agent.run, that drives the @smthrs/harness cell loop on the durable flow engine and returns a Stream<AgentEvent>.

  • Frame (harness/src/CellTurn.ts): compact the context window, seal a model step (content-keyed, replayed from the journal), extract the fenced cell block, run it in a QuickJS realm that lives for the whole run, resolve each ctx.call through CellCalls as its own durable boundary, witness the workspace before and after, apply discipline caps, then continue, complete, park, or suspend.
  • Model surface (harness/src/internal/cellPrompt.ts): ctx.call, ctx.flows, ctx.done, ctx.park, ctx.justify, ctx.checkpoint, ctx.base. Plain JavaScript over ctx.call by Will's 2026-08-20 ruling. A failed call resolves { ok: false, error }, it does not throw. Teaching changes are measured one at a time.
  • Capabilities are flows: StandardFlows.filesystem (read, write, edit, apply_patch, ls, glob, grep), StandardFlows.shell (bash), tests, memory, clock, approval; ChildFlows for subagents. Each is a FlowBinding.source(name, [FlowBinding.make({ flow, handler, publicError })]). A new capability for the cell is one more source in Agent.Options.flows.
  • Events (harness/src/AgentEvent.ts): DisciplineArmed, TurnOpened, ModelDelta, ModelRetried, ModelSettled, CellProduced, CellRejectedInFrame, CellCallStarted, CellCallSettled, CellPrinted, CellSettled, TransitionApplied, ReadOnlyDemanded, RepeatDemanded, NarrowedDemanded, UnmovedDemanded, UnresolvedDemanded, SufficiencyObserved, MutationObserved, CheckpointMinted, Suspended, CompactionSettled, SteeringDrained, TurnClosed, PermissionRequired, Aborted, Resolved.
  • Adapters: AgentSession runs the loop as a control-plane run (the production ControlExecutor); AgentAction runs it as one typed step with a declared output schema.
  • Policies at the model boundary: Budget (per run, journal-projected, fails closed) and QuotaPolicy (rate limit becomes a durable park). Agent.layer requires both.
  • Seats: a declared seat string like anthropic:claude-opus-5; SeatResolver resolves it to a live model, route, and context window. packages/smithers/src/NodeControl.ts installs the resolver that reads keys from the environment.
  • HTTP host: @smthrs/gateway serves /rpc, /projections, /sync, /health over Effect HttpRouter; smthrs serve binds it with a strict loopback rule.
Three loops exist. The harness cell loop serves the CLI control plane. @smthrs/chain is wrapped by the product app but never bound. The product app's chat goes through the server proxy to a managed-inference tool loop. The Jev harness builds on the first, and does not touch the other two.

3. OpenCode

OpenCode is a server plus clients. The server is an Effect HttpApi (Effect 4.0.0-beta.83 via a workspace catalog) defined in packages/protocol with handlers in packages/server; the clients are the TUI, the desktop app, and the web app packages/app. Reference versions: installed CLI 1.18.31; fresh clone of main at 5a83358 (2026-09-17); an older checkout 1.18.7 at ~/flows/reference/opencode.

3.1 The hosted app connects to any local server

  • https://app.opencode.ai serves the web app (verified 200). packages/app/src/entry.tsx: when location.hostname includes opencode.ai the default server URL is http://localhost:4096; a stored default server URL overrides it; the app has a server connection dialog.
  • CORS on the OpenCode server allows http://localhost:*, http://127.0.0.1:*, https://*.opencode.ai, tauri origins, plus --cors extras (packages/server/src/cors.ts). Our server must allow origin https://app.opencode.ai.
  • Basic auth: OPENCODE_SERVER_PASSWORD, username defaults to opencode. The app sends Authorization: Basic when a password is stored.
  • TUI: opencode attach http://localhost:4096 (installed 1.18.31) speaks the legacy v1 routes.
  • @opencode-ai/app is not on npm. @opencode-ai/sdk 1.18.31, @opencode-ai/ui 1.18.31, and @opencode-ai/client 0.0.0 are.

3.2 Two protocols, one app

The server exposes 188 routes at 1.18.31 (GET /doc is the OpenAPI 3.1 spec). Two families matter:

  • v1 (legacy): /session, /session/:id/message, /session/:id/prompt_async, /event SSE with {type, properties} payloads, /provider, /agent, /path, /project, /permission/:id/reply. Consumed through @opencode-ai/sdk/v2/client (frozen generation).
  • v2 (HttpApi): /api/*, defined in packages/protocol/src/groups/*.ts: health, location, agent, session, message, model, provider, integration, credential, permission, fs, command, skill, event, pty, question, reference, project-copy. Consumed through @opencode-ai/client/promise.

The app's utils/server-compat.ts builds a compatible API: it probes GET /api/health first (expects {healthy: true}); when that answers, the app uses the v2 client and falls back to legacy shims only for a few calls. The app's own e2e mock server has a protocol: "v2" mode that returns 404 on /global/health and serves only /api/* plus the SSE stream, which proves the app runs on a v2-only server.

3.5 Tool names with rich rendering

packages/session-ui/src/components/message-part.tsx renders these tool names specially: bash, read, edit, write, grep, glob, list, apply_patch, patch, todowrite, task, webfetch, websearch, question, skill, shell. Everything else gets the basic tool card (name, input, output). Smithers std flows already use read, edit, bash, write, grep, glob, apply_patch; ls maps to list.

3.6 What of OpenCode's tests we can reuse

  • Server tests (packages/opencode/test/server/*.test.ts) build OpenCode's own layers in-process. They are not runnable against a foreign server.
  • App e2e (packages/app/e2e, Playwright) run the real app against a Playwright route mock, not a server. Reusable two ways: the mock is the exact minimum contract, and the specs run unchanged against our real server by removing the mock and setting VITE_OPENCODE_SERVER_HOST/PORT.
  • sdk-v1-smoke.test.ts shows the pattern that transfers: a typed client (@opencode-ai/client for v2, @opencode-ai/sdk for v1) pointed at a base URL. Our contract tests use that shape.
  • OpenAPI: GET /doc from the installed CLI (saved at scratchpad opencode/openapi.json, 472 schemas) is the schema oracle for v1; packages/protocol is the oracle for v2.

4. Open questions to close before build

  1. Exact route and event trace of the hosted app against a logging proxy for: connect, list, create, prompt, tool call, permission, done. Closes the contract table above.
  2. Whether Safari allows https://app.opencode.ai to fetch http://localhost:4096. Chrome and Firefox treat localhost as potentially trustworthy. OpenCode ships this path, so it works in their supported browsers; we verify ours.
  3. Whether the app needs /api/model populated to enable the composer, or accepts a session created with a fixed model.
  4. How the app renders a tool item whose name it does not know (expected: basic card with name, input, output).

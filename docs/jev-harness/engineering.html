Jev Harness: Engineering

Shipping architecture, reviewed 2026-09-19. The original spike evidence remains in the composition and scaffold briefs; dated measurements remain in the research log.

Summary. @smthrs/opencode adapts the existing durable Smithers cell loop to OpenCode protocol v1. The hosted app and the 1.18.31 terminal client use the same server. Classifier is the new core API, with Effect Schema declarations and an injected Evaluator. The server owns the health projection and the CLI owns its Node host composition.

1. Shipping components

ComponentResponsibility

Routes.ts, Protocol.tsThe v1 HTTP contract and three compatibility routes: /api/health, /api/session, /api/reference. See design section 6 and the live trace. No OpenCode runtime dependency; the pinned SDK is a test dependency.

Turns.tsSerialize admission per session, persist prompts, drive idle sessions, steer busy ones, answer permissions, abort and resume open executions on boot.
Store.tsSessions, projected messages, parts, turns, grants and health records in <directory>/.smithers/opencode.sqlite, alongside the engine tables.
Projection.tsFold harness events into native file/shell cards and generic cell/classify/health/demand cards. Stable part ids prevent duplicate cards on replay. Session updates carry health titles, tokens and configured model pricing.
Events.tsA bounded SSE hub. Subscribe before reading reconnect state or delivering the greeting so permission and completion events cannot fall between bootstrap and the live stream.
Health.tsOne asynchronous evaluation per frame, plus park/answer triggers. Pure color rule from design section 3.3, 1.5-second health deadline, final reading from settled facts. Health failure never fails a turn.
Classifier.ts, Evaluator.tsTyped boolean, choice and score questions. Encode through the state schema, validate JSON, decode probabilities, and return typed transport errors. The gateway layer makes one request; the host owns retry and transport recovery.
std/Classify.ts, Classifiers.tsAd-hoc classify and curated relevance, check-verdict and edit-risk doors. At most 64 states, 32 KiB of encoded JSON per state, and eight concurrent evaluations.
CompletionClaim.ts, CellTurn.tsJudge evidence-bearing completions, give bounded correction frames, and reject invented work. The reading is a durable boundary so replay does not change the decision or pay for it again. Every nonempty completion with a task is judged when the brake is enabled.

2. Boundaries and recovery

  • The kernel checks filesystem, shell and model authority. Rebuilding a model connection pool must retain its HTTP guard.
  • A saved shell grant covers only a simple literal command with the displayed program pattern. Compound shell syntax and interpreter programs require individual approval.
  • The host uses the existing process reaper beneath the guarded spawner to terminate child process groups and escalate after a short grace period.
  • Clarification is conversational: the agent completes with its question, and the next user prompt starts the follow-up. Model-requested question parks are disabled because this release has no question-card reply routes. Guarded tool permissions still park normally.
  • Journaled, settled calls replay without repeating their side effects. A shell operation interrupted before its result was journaled has an uncertain external outcome and can run again on recovery. This is not an exactly-once guarantee for an unfinished external process.
  • The gateway key is mandatory for a real seat because an evidence-bearing completion the brake cannot judge fails. The independent health projection can still become gray without stopping the run.
  • The completion judge sends bounded factual call receipts as well as checks. A successful classification or file read must not be described to Jev as an empty record.

4. Launch limits

No custom UI, local app hosting flag, question-card UI, review diff endpoint, PTY, MCP, LSP, worktree management, fork or revert implementation. The hosted app can change independently of the pinned contract. The cheap seat can waste frames or fail a task; the completion brake is not a general correctness oracle. Its evidence cannot establish that every requested file changed or that every answer about the repository is correct.

The product's day-one targets remain targets until measured: three real tasks, unprompted classifier use, operator agreement on color changes, recovery, and cost share. The current operator procedure and measured limitations are in runbook.md; the final review records which gates actually ran.

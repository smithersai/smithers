Jev Harness: Design

Draft 1, 2026-09-17. Specifies every surface the product doc requires (R1 to R12): user flows, the UI as OpenCode renders it, the health color, the Classifier API, the cell-facing classify flows, and the server contract. Requirement ids are cited inline.

3. Health color

One Jev evaluation per frame, from the server, never from the cell. It reads the run and answers three questions; the color is a pure function of the answers and the frame facts the harness already journals.

3.1 State sent to Jev

{
  task: string,                       // the prompt, first 2 KiB
  frame: number, maxFrames: number,
  framesSinceEdit: number,            // from MutationObserved
  demands: string[],                  // discipline demands issued so far, newest last
  lastCalls: [{ flow, ok, summary }], // last 12 calls, one line each
  lastPrints: string,                 // last 2 KiB the model printed to itself
  parked: "none" | "permission" | "question" | "quota",
  lastTransition: "continue" | "complete" | "park"
}

3.2 Questions

progress:   { type: "score",   instructions: "Where is this run?", criteria: ["stuck", "exploring", "progressing", "verifying", "done"] }
stuck:      { type: "boolean", instructions: "Is the run repeating itself or reading without acting?" }
needsHuman: { type: "boolean", instructions: "Does the run need a person to answer, approve, or decide before it can continue?" }

3.3 Color

First match wins, in three blocks: the facts, then whether there is an answer at all, then the answers. The order inside the third block is deliberate and is stated under the table.

#Rule (first match wins)ColorReason line
1parked !== "none" redwaiting for approval, waiting for an answer, waiting for quota
2a usage limit ended the run (stoppedBy, off the provider's normalized code) redstopped: openai:gpt is out of quota
2bthe harness ended the run (endedBy, off HarnessError.code, or frame_budget for a spent budget, or unknown for a failure carrying neither) redstopped: the run reported work it never recorded, stopped: the frame budget of 40 is exhausted, stopped: the turn failed
3no answers, or confidence < 0.5 on every question grayhealth unavailable: …, health uncertain, interrupted
4needsHuman.probability ≥ 0.7 redneeds you (82%)
5a demand was issued this frame yellowread-only demanded, claim demanded
6progress.label === "done" with confidence ≥ 0.5, or lastTransition === "complete" greendone, verifying
7stuck.probability ≥ 0.6 yellowrepeating itself (66%)
8progress.score ≤ 1 with framesSinceEdit ≥ 4 yellowexploring · 4 frames, no edit yet
9otherwise greenprogressing, verifying

Gray means one thing. Gray is health is unavailable, and nothing else. A cap or a kill that ended a run is red with a reason naming it, because an operator who walked away reads a gray dot on an idle session as Jev having been down while the run carried on, and nothing was carrying on. Measured on 2026-09-18: a run the harness killed on an unproven claim kept a gray dot reading failed, which is the same dot a missing gateway key writes. Only the operator's own Stop is gray, because nothing about it is theirs to act on. Rule 2b is read off a typed code every time and never off a sentence, the same rule as rule 2.

A missed deadline is not unavailability. One health call over its 1.5 s deadline keeps the color the run already had rather than repainting the dot gray; every other transport failure is the gateway saying it cannot serve the call, and repaints at once. The deadline is not too tight: Jev answers in about 300 ms end to end, 1500 ms is five times that, and the retry policy already gives a blip a second chance inside it, so widening it would move the flicker later and delay every gray that is real. Three missed deadlines in a row do go gray, naming the streak, so a dot is never more than three frames older than something that confirmed it. The flicker came up in four of sixteen measured turns on 2026-09-18 and changed nothing about any of them.

Why this order. The facts come first because they need no judgment: waiting for approval is not an opinion, and neither is a completion the harness handed back. Then, among the answers, needing a person beats everything, because that is the one color an operator has to act on. Arrival beats repetition: a run that re-read a file on its way to a correct answer is not stuck, so a confident done, or a turn whose last transition was complete, is green even when stuck is over its threshold. Testing stuck first made the rule contradict its own answers, and a finished run kept the contradiction forever: the live keyed drive ended a bug fix yellow repeating itself (69%) over progress: done (89%) · stuck: yes (69%) · needs a person: no (12%).

When it is read. Once per evaluation, and twice more without asking Jev again. A permission a person answers clears parked at the answer and asks again from the same frame, because parked is a fact about right now and rule 1 short-circuits before any answer is read. And a turn that resolves reads the rule once more over its own final facts (nothing parked, no demand outstanding) and the last answers Jev gave, so the dot a finished session keeps is the color its last state earned (F6). That final reading makes no gateway request. The footer counts logical evaluations, including each batch state; retries are not separate evaluations. Spend uses reported token usage.

What a resolved turn ends on. The last reading keeps the turn's real lastTransition rather than forcing it to complete. A run that finished applies a complete transition and the controller closes the turn on that transition's own words; a run whose frame budget ran out applies none and gets the budget notice instead, so a resolved turn whose last transition is not complete carries frame_budget as its endedBy and is red naming the budget. It used to be green over an answer that is only the notice. A completed turn with no health reading is green reading answered, including when it resolves before the frame's health evaluation answers. This final fallback does not exempt its completion from the separate harness judge.

Rendering. The dot is a prefix on the session title (session.updated with 🟢 Fix flaky unit test), which is what the sidebar and header show without any UI change. A health tool item is emitted only on a color change, with the reason line as its input.description and its title, and the three answers as its output. The turn's last reading is the exception and always writes its card: a run whose budget ran out while a permission card was open ended red under the red rule 1 had already written, so the only reason an operator could read said waiting for approval about a card that was gone, and the same silence masked rule 2 and rule 2b on any turn that was already red. The reason has to be in the input: the app's generic card reads its subtitle from input.description and never reads a title, and the TUI prints the input alone. The dot is removed from the title when the session is archived.

Cost and timing. One call per frame, about 900 input tokens, under $0.00005 and under 0.5 s, run concurrently with the next model call so it never delays the loop. Deadline 1.5 s. Failure never touches the run (R10).

4. Classifier, the one new core API

Lives in @smthrs/model as Classifier.ts with its transport in Evaluator.ts. Effect Schema declares the state and the questions; the answer type is inferred; the transport is a service so Jev over the Vercel gateway is one layer and a scripted evaluator is another (R8).

import * as Classifier from "@smthrs/model/Classifier"
import * as Evaluator from "@smthrs/model/Evaluator"
import { Config, Effect, Layer, Schema } from "effect"

export const Relevance = Classifier.make("triage/relevance", {
  description: "Whether a file must change for the task, and its role.",
  state: Schema.Struct({ task: Schema.String, file: Schema.String, excerpt: Schema.String }),
  questions: {
    relevant: Classifier.boolean({
      instructions: "Does this file need to change for the task?",
      criteria: { true: "the fix or its test lives here", false: "unrelated or only imported" }
    }),
    role: Classifier.choice({
      instructions: "What is this file's role?",
      criteria: { implementation: "code under test", fixture: "test data or setup", unrelated: "nothing to do with the task" }
    }),
    risk: Classifier.score({
      instructions: "How risky is editing this file?",
      criteria: ["none", "low", "medium", "high"]
    })
  }
})

// Inferred:
// Relevance.Answer = {
//   relevant: { value: boolean; probability: number },
//   role:     { value: "implementation" | "fixture" | "unrelated"; probabilities: Record<..., number>; confidence: number },
//   risk:     { value: number; label: "none" | "low" | "medium" | "high"; probabilities: Record<string, number>; confidence: number }
// }

const program = Effect.gen(function*() {
  const answer = yield* Relevance.evaluate({ task, file, excerpt })          // Effect<Answer, ClassifierError, Evaluator>
  const many   = yield* Relevance.evaluateAll(states, { concurrency: 8 })    // Effect<ReadonlyArray<Result<Answer, ClassifierError>>, never, Evaluator>
  return Classifier.confident(answer.role, 0.7)                              // Option<"implementation" | ...>
})

// Production: Jev through the Vercel AI Gateway. Key from the environment, zero data retention on.
const live = Evaluator.layerVercelGateway({ apiKey: Config.Redacted("AI_GATEWAY_API_KEY"), model: "typesafe-ai/jev", timeoutMs: 1500 })
// Tests: scripted answers, no network.
const scripted = Evaluator.layerScripted((request) => ({ relevant: { probability: 0.9 }, role: { choice: "implementation" }, risk: { score: 1 } }))
SurfaceContract
Classifier.make(id, { description, state, questions })Returns { id, description, state, questions, evaluate, evaluateAll, digest }. digest is the canonical hash of the declaration, folded into the durable call key so a changed question never replays an old answer.
Classifier.boolean / choice / scoreQuestion constructors. choice keys become a literal union; score criteria become rung labels; at most 255 choice keys, at least 2 score rungs, enforced at construction.
Classifier.Question, Classifier.AnswerEffect Schemas for the ad-hoc path, so a model-authored question is decoded before it reaches the transport.
Evaluator.EvaluatorService with one method evaluate({ state, questions }) → Effect<{ answers, usage?, latencyMs }, EvaluatorError>.
Evaluator.layerVercelGateway(options)The wire protocol from apps/server/src/jev.ts over @smthrs/kernel/HttpClient. Options: apiKey, model, timeoutMs, zeroDataRetention (default true), baseUrl.
Evaluator.layerScripted(fn), Evaluator.layerUnavailable()Evidence-based offline scripts and explicit classifier outage tests. Agent hosts must select a real or scripted judge before resources open; a missing gateway key refuses startup.
ClassifierError{ code: "unreachable" | "refused" | "empty" | "timeout" | "invalid_answer" | "invalid_question", status?, message }. Typed, never thrown.
Classifier.confident(answer, floor)Option of the value when confidence (or the boolean's distance from 0.5, doubled) is at or above the floor.

5. The cell-facing doors

The agent reaches Jev the way it reaches a subagent: through ctx.call (R7). Two flows, both from one FlowBinding.source("std/classify", …) added to StandardFlows.

5.1 classify: model-authored questions

// Input (one of):
{ state: Json, questions: Record<string, Question> }
{ states: Json[], questions: Record<string, Question> }        // batched, evaluated concurrently, ≤ 64 states

// Output:
{ answers: Record<string, Answer>, confidence: Record<string, number>, latencyMs, usage? }
{ results: Array<{ ok: true, state, answers, confidence } | { ok: false, state, error }>, latencyMs, usage? }
// Optional usage: { inputTokens: number, outputTokens: number }.
// Batch usage sums the reported usage of successful states.
// What the model reads in ctx.flows (kept to two lines, paid for under the concierge cap):
classify: Ask Jev typed questions about any JSON state: boolean, choice (named options), or score (ordered rubric).
           Answers carry probabilities and confidence. Batch with `states` to judge many things in one call. No text comes back.

5.2 classify/<id>: curated classifiers

StandardFlows.classify(services, { classifiers: [Relevance, CheckVerdict, …] }) takes a context containing Evaluator.Evaluator and registers the ad-hoc door plus one flow per declared classifier, named classify/triage/relevance, whose input schema is the classifier's state (or { states }) and whose description is the classifier's. The catalog shows the model exactly what each one judges. Day one ships three: triage/relevance, check/verdict (did this command fail for the right reason), edit/risk.

5.3 Durability

Every classify call is an ordinary sealed call: content-addressed on the classifier digest, the state, and the questions, so a resumed run replays the answer without paying Jev again, and a changed question is a new key.

6. Server contract

Decision 2026-09-17, after the live trace: the server speaks OpenCode protocol v1, not v2. The hosted app probes GET /global/health first and runs v1 whenever it answers {healthy: true}; it picks v2 only when that probe fails and /api/health carries a numeric pid. Against every shipping server the app runs v1 end to end, and v1 was traced through prompt, tool call, permission card, reload, and rename. Forced v2 needed proxy shims for routes OpenCode main does not serve and never completed a turn, so its tool and text events were never observed. The authoritative contract is now trace/summary.md Run A (routes per step, events per step, envelope {directory, project, payload: {id, type, properties}} on /global/event) and the 1.18.31 OpenAPI schemas. The tables below describe the shipping v1 adapter; the historical v2 investigation remains in the trace. Consequences: /api/health answers {healthy: true} without pid; the app also calls three v2 routes in v1 mode (/api/health, /api/session?limit=5000&order=desc, /api/reference) and they must answer; prompts arrive on POST /session/:id/prompt_async with {messageID, agent, model: {modelID, providerID}, parts: [{id, type: "text", text}]} and get 204; permissions are answered on POST /session/:id/permissions/:permissionID with {response}; the timeline is driven by message.updated, message.part.updated (tool parts carry state.status), message.part.delta, session.status, session.idle, session.updated, permission.asked, permission.replied. The TUI (opencode attach) speaks the same protocol, so it is no longer out of scope by construction. In headless Chromium the blocker is Local Network Access permission, not mixed content; headed Chrome prompts once.

The shipping routes and events below implement Run A of the trace. Unknown routes return a JSON 404 with CORS headers. One server serves one directory, one agent, and the configured seat.

Claim the record does not supportThe completion is handed back once with a demand card titled claim, and the run gets a frame to answer. Up to three times: a run that claims it is done before it has done anything is told to go and do it, not argued with forever. What comes back then stands, unless it reports a command the run never ran or a result it never got, which ends the turn with UnknownError and A completion reporting work this run never recorded: invented 0.95 (complete 0.07, overclaims 0.93, neither of which decides this), finish error, and no answer. Two shapes are settled by measurement rather than by taste. The cap used to end the brake rather than the run, so the second claim stood unread: measured live, one run bounced at frame 1 re-claimed the identical sentence and finished stop on the tests pass over a repository whose test exits 1. And the verdict used to ride on is the task done and does the claim assert more than the evidence shows, which killed true answers: zero of five live question-shaped turns answered at all, and one live CI dispatch in four died over a planted bug that was fixed. Scored on 2026-09-19 against eighteen completion states asked six times each, the first of those two fired on eight of twelve honest completions and two of six lies, the second on five of twelve honest ones; the narrow question fired on none of the twelve and ended four of the six lies. All three still hand the completion back, because a bounce costs a frame rather than an answer; only the narrow one refuses. R10 is the reason the change went this way rather than to a higher threshold: Jev ranks, gates and reports, so it may refuse a sentence its own evidence contradicts and may not be the authority on whether a task is finished.

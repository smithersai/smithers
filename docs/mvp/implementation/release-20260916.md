## Engineering conclusions

- **Source identity.** Review, checks and landing must identify the same
  immutable candidate and base. A check on an editor tree cannot certify a
  different candidate.
- **Saved setup.** Materializing workflow configuration must not silently
  change the source selected for landing. Preserve saved setup and editor
  state while checking the exact candidate.
- **Native helpers.** Advertise a capability only after the installed helper
  passes its runtime verification. Source review alone does not prove that a
  host has the reviewed artifact.
- **Bounded commands.** Exercise the complete encoded provider command against
  operating-system argument limits. An isolated interpreter smoke test does
  not prove that the actual maintenance command can start.
- **Source retention.** Required source must remain addressable after checks
  and later failures. An operation receipt binds the request, base and exact
  bytes; copied or altered receipts must be refused.
- **Mirror boundaries.** Internal source and review refs must stay outside
  ordinary repository mirroring, including transfer, pruning and retry.
- **Request ownership.** In-flight upstream work belongs to its request.
  Completed cache data may be shared; another request must not depend on a
  suspended request's I/O.
- **Durable admission.** Preserve a guidance request until actual admission.
  Recovery must not provision extra work, replay a completed operation or
  infer an inactive setting from missing local state.
- **Responsive interaction.** Test deliberately unresolved provisioning and
  reads. Chat stays usable, duplicate commands coalesce and progress settles
  only after the actual result.
- **Evidence limits.** Source tests, artifact verification and served-response
  observations establish different facts. A later successful attempt does not
  turn an earlier partial result into a completed landing.

## Reproducible verification

Use disposable local fixtures and real dependencies. Retain the exact source,
command, output and limitations for each observation. Keep failures visible and
compare them against the unmodified source before attributing a regression.

Public examples use repository-relative paths and synthetic input. Provider
account observations and hosted operations remain private even when historical.
